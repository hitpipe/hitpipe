# HTTPS-проверка входа в IAM

Запускайте стенд в отдельной одноразовой Ubuntu VM. Нужны Docker Engine с Compose v2, Go версии из `services/iam/go.mod`, Node.js 22, OpenSSL, curl и `certutil` из пакета `libnss3-tools`. Docker работает внутри VM. Если Chromium ещё не установлен, выполните в VM следующие команды из этой папки.

```bash
npm ci --no-audit --no-fund
npx playwright install --with-deps chromium --only-shell
HIT106_ISOLATED_LAB=1 ./run.sh
```

Если Go установлен отдельно, передайте путь через `HIT106_GO`. Если браузеры лежат в отдельном кэше, укажите его через `PLAYWRIGHT_BROWSERS_PATH`.

Скрипт собирает Keycloak с провайдером HIT-105, запускает отдельные PostgreSQL для Keycloak и IAM на временных файловых системах и принимает письма через Mailpit. Keycloak и IAM используют разные адреса loopback (`127.0.0.1` и `127.0.0.2`), чтобы cookies одного сервиса не отправлялись другому. Конфиденциальный клиент принимает один URI обратного вызова и требует PKCE S256. Сертификаты подписывает временный УЦ, которому доверяют только процессы проверки. Данные и секреты стенда удаляются при завершении скрипта.

Playwright проверяет регистрацию с кодом из реального письма, последующий вход подтверждённого пользователя, свойства cookie, число учётных записей и сессий, отказ при повторном или отменённом callback, отказ после перезапуска IAM и запрет входа с неподтверждённым email. Диагностика не выводит коды, cookies, токены и пароли.

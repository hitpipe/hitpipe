# Чтение сохранённой сессии IAM · HIT-68

Адаптер реализует существующий `authenticatesession.SessionLookup` и возвращает
`sessionpolicy.Snapshot`. Policy, потребитель и их правила остаются прежними.
Это отдельная деталь IAM, подготовленная к будущему подключению в сервер.

## Как использовать

Владелец IAM создаёт `pgxpool.Pool` для **своей** базы и роли, задаёт `MaxConns=5`
(допустимый максимум — 10), затем передаёт пул в `New`. Пул остаётся собственностью
вызывающего кода; адаптер не открывает второй пул и не закрывает переданный.
Настоящий сервер обязан отдельно настроить проверенное соединение и безопасную
диагностику без аргументов SQL. Тестовый `sslmode=disable` относится только к
одноразовому контейнеру на loopback и не является настройкой рабочего соединения.

Перед вызовом существующего потребителя IAM получает `Reference(opaqueSecret)`.
Это SHA-256 **точных байтов** opaque session из `__Host-hp_session` либо принятого
внутреннего заголовка. Полученная lowercase hex-строка помещается в существующий
внутренний строковый порт; она совместима с его проверкой reference даже когда
исходная cookie начинается с `-` или `_`. В SQL передаются 32 байта digest и
выполняется поиск по `session_hash`. Способ кодирования случайной cookie этим не
выбирается; проверка длины 43–128 взята из принятого wire-контракта. Проверка длины
не доказывает энтропию: создание и хранение секрета остаются обязанностью issuer.

Слой будущего IAM transport должен вычислять reference сам. Принимать от браузера
готовый hash, публичный `session_id`, UUID пользователя или произвольную ссылку
вместо секрета запрещено. Здесь не добавлены HTTP-обработчик и выпуск cookie.

Каждый `Lookup` делает новый параметризованный `SELECT` из `hp_iam.sessions`.
Читаются только `created_at`, `expires_at`, `idle_expires_at` и наличие `revoked_at`.
В snapshot не попадают секрет, digest, CSRF, UUID, профиль, роли и epoch.
Отсутствующая запись — `Found=false`; наличие записи не означает пригодность
сессии: это по-прежнему решают существующие consumer/policy и отдельные полномочия.

Нет кеша, продления сессии, изменения активности или сохранённой транзакции.
Срок запроса ограничен двумя секундами либо более ранним сроком вызывающего кода.
Ошибка PostgreSQL даёт фиксированную ошибку `session_lookup_unavailable`, отмена —
стандартную безопасную ошибку context; оба пути возвращают пустой snapshot.

## Что и как проверяется

Из корня репозитория, с Go 1.27.2 в `PATH` и доступным Docker:

```sh
python3 services/iam/tools/check_postgres_session_lookup.py
```

Можно указать `--go /путь/к/go`. Скрипт сам создаёт и удаляет выделенные контейнер
PostgreSQL 18.6 и выделенную сеть. Порт доступен только на `127.0.0.1`, данные
временные. Внешний DSN не принимается. `trust` разрешён только для этого закрытого
тестового контейнера; реальная аутентификация базы этой проверкой не подтверждается.

В контейнер целиком применяется SQL IAM из принятого `PERSISTENCE.md`, без правок
таблиц, ограничений и связей. Исходные байты проверяются по SHA-256. Runtime login
не является суперпользователем, наследует только `hp_iam_app` и работает с
`default_transaction_read_only=on`; подготовкой/отзывом тестовых данных занимается
отдельный fixture administrator. Содержимое строк и их MVCC-версии сравниваются до
и после чтений, чтобы обнаружить также незаметное продление или пустой UPDATE.

Сохраняются команды и полные протоколы обычных тестов, тестов с настоящей PostgreSQL
и `-race`, `go vet` и сборки. Проверяются точные сроки/признаки, неизвестная сессия,
чтение сразу после committed revoke, повторное применение старого consumer,
ошибки прав базы, отмена уже заблокированного запроса, внутренний timeout,
закрытый пул, параллельные чтения и отсутствие раскрытия секрета/reference в ошибке.
Пропущенные PostgreSQL-тесты не считаются положительным результатом.

Тесты адаптера **не подтверждают** работающий вход/OIDC, бизнес-полномочия,
доверенный источник времени, общий протокол отзыва и start gate, TLS рабочего

этой доработкой не изменяются. Изменение `revoked_at` выполняет fixture administrator,
не адаптер; оно не выдаётся за реализацию общей процедуры отзыва.

# HIT-83: создание сессии после проверенного входа

Готов компонент, который принимает проверенное одноразовое подтверждение входа и
сохраняет пользователя вместе с сессией одной транзакцией PostgreSQL. При ошибке
или неопределённости он не возвращает успех и секреты.

## Что сделано

- Пользователь определяется только парой «провайдер, внутренний идентификатор»
  (`issuer`, `subject`). Email не передаётся как источник идентичности. Параллельные
  входы не создают дубликат пользователя; его прежний профиль сохраняется.
- Секреты сессии и CSRF создаются независимо через `crypto/rand`; в SQL передаются
  только SHA-256. Обычное форматирование и JSON скрывают секреты.
- Подтверждение входа потребляется один раз. Неподтверждённая почта, истёкшая
  попытка, повтор, неизвестное время, необходимость ротации и незавершённый отзыв
  запрещают выдачу. Обязательные подключения не имеют разрешающих заглушек.
- Прежние правила сессии, обработчик проверки и оптимизированное чтение сохранены.
  Созданная сессия читается ими; отозванная и истёкшая отвергаются.
- Потерянный ответ на COMMIT и отмена не выдаются за гарантированный откат:
  строка уже может существовать, но положительного результата и секретов нет.

повторён успешно. История первого запуска сохранена в рабочем журнале аудита.

## Как повторить

```sh
python3 services/iam/tools/check_session_issuance.py --evidence-dir /tmp/hit83-check
```

Нужны Docker, Go 1.27.2 и не менее 512 МиБ свободного места. Каталог протоколов
должен быть пустым. При необходимости укажите `--go /путь/к/go`.

## Что остаётся следующей задаче

Результат можно подключать к настоящему входу в HIT-106. Сейчас одноразовый
проверяющий, доверенные часы и проверка разрешения управляются тестами; их рабочие
подключения, долговечные OIDC-попытки, HTTP-ответ и доставка CSRF ещё не написаны.
Рабочие сроки сессии должны быть заданы явно: значений по умолчанию нет, а числа
8/24 часа в тестах — тестовые входы, не новая конфигурация продукта.

Общий отзыв и ротация, регистрация с кодом и развёртывание требуют своих реализаций.
HIT-83 не заявляет готовность этих частей. Метаданные защищённой cookie и порядок
безопасного подключения описаны в [инструкции](../../docs/SESSION_ISSUANCE_RU.md).

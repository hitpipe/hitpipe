# HIT-85 — результат для проверки

Добавлено защищённое чтение своего профиля: BFF обращается к приватному
`GET /api/v1/profile` с сертификатом и сессией. В ответе — только идентификатор
владельца, имя, часовой пояс и версия профиля. Владельца определяет база IAM.

## Что можно принять

Обработчик, который действительно получает профиль через HTTPS, проверяет
сохранённую сессию в PostgreSQL и точные байты приватного файла. При чужом
сертификате, отозванной сессии, смене владельца/версии во время чтения,
повреждённом или отсутствующем файле успешный профиль не отправляется.
Двухсекундный срок охватывает критическую операцию и начало ответа;
отправка принудительно начинается, пока удерживается обязательный допуск.

Переиспользованы HIT-68 и принятый HIT-84. Глобальное чтение собственного профиля
не создаёт выдуманных разрешений рабочего пространства. Схемы OAS/SQL,
существующее ядро, SessionLookup, go.mod/go.sum и другие сервисы не изменены.
В файловом адаптере проверяются права, отсутствие symlink/обхода пути, SHA-256,
строгий JSON и Unicode. Старый профиль из кэша после ошибки не возвращается.

## Граница результата

Этот результат — обработчик и проверенная временная композиция, готовые для
дальнейшего подключения. Рабочий сервер, BFF, Keycloak и общий координатор HIT-69
здесь не развёрнуты. Обязательный порт допуска остаётся явно внедряемым:
разрешающей реализации по умолчанию нет, тестовая не выдаётся за рабочую.
Запись профиля, GET session, cookies/login/logout и очистка данных не входят в HIT-85.
Частный формат файлов и digest описан в инструкции; новый продуктовый TTL не введён.

Внешний результат хранится в `.project-os/results/HIT-85.json`. Его регистрация и
серверная проверка готовности оформляются отдельно; этот отчёт не выставляет
PASS и не принимает задачу за руководителя.

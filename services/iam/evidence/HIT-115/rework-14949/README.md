# HIT-115 · Приватная авторизация и регистрация IAM

IAM принимает два служебных запроса на 8443. TLS 1.3 проверяет цепочку клиента и срок сертификата. Явный инвентарь связывает точный DNS SAN и SHA-256 сертификата с сервисом, UUID runtime, поколением и UUID загрузки. При регистрации эти пять полей сверяются с инвентарём. При авторизации связь с runtime берётся из того же инвентаря, а права человека определяет существующая проверка действительной сессии и текущих SQL-фактов IAM.

## Доработка после независимого ревью

HTTP-обработчик /internal/v1/authorize теперь явно вызывает строгий Request.UnmarshalJSON из HIT-84. Код валидатора сверили с принятой версией по Git blob 11975280134893be479d19de843e3adb6a22ea29. Тест через проверенное TLS 1.3/mTLS отправил 25 реальных POST. Два корректных тела со значением UUID и null дошли до контролируемого backend с исходной семантикой. 23 некорректных тела, включая неизвестные поля, дубликаты ключей, отсутствующий resource_id и неверные UUID, получили HTTP 400 до вызова backend. Действительный проход с PostgreSQL проверен отдельно полным интеграционным набором. ## Запуск и текущая авторизация

- `POST /internal/v1/runtime/register` принимает доверенную комбинацию сервис, runtime, generation, boot и fingerprint только от соответствующего mTLS-клиента. Первый согласованный вызов записывает `SYNCING`. Повтор обновляет наблюдение той же загрузки. Для замены загрузки требуются одобренная новая комбинация, рост поколения и уже проверенная запись о fencing предыдущего процесса. Время регистрации и пропущенный heartbeat такого доказательства не дают.
- Снимок содержит текущую идентичность, состояние и полную выборку актуальных собственных записей deny из принимаемой базы. Версия снимка монотонна для runtime и хранится в существующем `last_observed_at` с точностью до микросекунд. Она служит порядку снимков и не подменяет независимые scope epoch. Неполный инвентарь, невалидные данные, конфликт или ошибка чтения закрывают доступ.
- Композиция `privateiam.New` требует отдельные доверенные часы, явный инвентарь и реализацию `ResourceAuthority` от соответствующего владельца. `Listen` слушает указанный частный адрес или loopback на 8443. Вызов `Start` устанавливает свежий снимок для загрузки IAM на том же объекте `startgate` и подтверждает точный снимок в PostgreSQL перед переходом локального gate в `OPEN`. Отдельный новый экземпляр требует новую утверждённую загрузку. Сетевой endpoint регистрации сам по себе не подтверждает применение снимка чужим процессом. Для проверяемого положительного сценария mTLS-клиентом выступает этот же экземпляр IAM после `Start`.
- `POST /internal/v1/authorize` принимает непрозрачную сессию в штатном заголовке и точный JSON `AuthorizeRequest`. Приватное чтение метаданных выбирает актуальную эпоху пространства. Защищённое чтение сессии, членства и текущих прав проходит через `startgate` и `authorizeaction.Execute`. Перед записью ответа тот же gate проверяет точные сессию, пространство и применимое подключение. Авторизация повторяет чтение собственных фактов и доказательство владельца. Внутри защищённого callback сверяются свежий deny snapshot и эпоха, затем выполняется фактический `Write` и `Flush`. Конкретное `MEMBERSHIP subject_id` по имеющимся данным не отображается на пользователя. При относящемся запрете пространство получает консервативный отказ.
- Ошибки содержат ограниченный код, нейтральное сообщение и ID запроса. Сертификат авторизует служебного участника транспорта. При доступе к ресурсу независимо проверяются действительная сессия, роль и явное доказательство владельца. Тесты используют узкий управляемый resolver только для конкретного синтетического дела.

## Воспроизведение

В одноразовой Ubuntu VM с Go 1.27.2, C-компилятором и Docker из checkout проверяемого SHA выполнить:

```sh
CGO_ENABLED=1 python3 services/iam/tools/check_authorization.py --evidence-dir /tmp/hit115-postgres
(cd services/iam && CGO_ENABLED=1 go test -race -count=1 ./... && go vet ./... && go build ./...)
python3 services/platform/tools/check_start_gate.py --evidence-dir /tmp/hit115-gate
```

Точный проверенный коммит — `0ff7f039ccaf450d60a59cd9cc0504c13e032b08`. В изолированной VM Ubuntu 24.04.5 с Go 1.27.2 прошли все восемь сценариев mTLS и PostgreSQL 18.7, весь набор интеграций с `-race`, обычные Go race, vet и сборка. Отдельный набор Platform прошёл десять прогонов с `-race`. Стенд удалил PostgreSQL-контейнер, сеть и закрыл порт 8443. [Команды, версии и коды завершения](verification.json) · [Полный журнал Go race и PostgreSQL](iam/postgres-race.log)

Область результата включает частный IAM transport и одно продолжение работы в провизионированном процессе. Рабочие подключения сервисов-владельцев и BFF, подтверждение удалённого gate, распределённый отзыв, реальный fencing, health-интеграция и выкатка остаются отдельными работами.

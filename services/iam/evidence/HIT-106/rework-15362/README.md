# HIT-106 — браузерная проверка после ревью №15362

[Ревью №15362](https://hitpipe.atlassian.net/browse/HIT-106?focusedCommentId=15362) потребовало подтвердить раздельную идентичность аккаунтов с одинаковым верифицированным email и проверки одноразового кода в браузере.

## Два аккаунта с одним подтверждённым email

В одноразовом realm два тестовых аккаунта созданы с одним подтверждённым адресом, разными именами входа и разными `subject`. Chromium выполнил три HTTPS-входа через Keycloak. Для каждой выданной сессии тестовый сервер прочитал из PostgreSQL связанную запись и сравнил пару `issuer`/`subject` с данными Keycloak. Появились два отдельных аккаунта HitPipe и две сессии. Повторный вход первого пользователя добавил третью сессию к его же аккаунту.

## Одноразовый код и ограничения

Chromium заполнил формы реального расширения Keycloak и получил коды через Mailpit. Проверены отказ для неверного и истёкшего кода, блокировка после пяти ошибок, отказ при немедленной повторной отправке, аннулирование старого кода после выдачи нового, отсутствие второй авторизации при повторном вводе использованного кода, лимит пяти писем за скользящий час и одна выданная сессия при двух одновременных запросах. Тест сдвигает временные поля сгенерированных записей в одноразовой базе, чтобы проверить истечение срока и переход между окнами без ожидания. Проверки используют исходную политику расширения.

## Воспроизведение и журналы

Точный проверенный коммит, команды, окружение, результаты и контрольные суммы сохранены в [протоколе](verification.json). [Краткий протокол запуска](review-transcript.txt) содержит результаты 14 браузерных сценариев, включая восемь первоначальных. Полные журналы доступны для [Chromium и Mailpit](browser.log), [Go](go.log) и [PostgreSQL](postgres/postgres-race.log). Проверка PostgreSQL включает подтверждение отката и отказа при потерянном подтверждении COMMIT. Отдельный тест замеров задержки `TestHIT82LatencySamples` штатно пропущен без включения режима замеров.

Стенд работал на отдельной Ubuntu VM с собственной тестовой CA и временными данными. Разрешение одинакового email применялось только к одноразовому realm для заключительного сценария. Тестовый обработчик доступен только в сборке с тегом `hit106lab` и выводит хеши идентификаторов. Сведения об очистке контейнеров и слушателей сохранены в [журнале](cleanup.log).

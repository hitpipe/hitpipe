# HIT-138 · запуск одного процесса IAM

Точка входа — `services/iam/cmd/iam`. Процесс использует один пул PostgreSQL и
один шлюз начала работы HIT-115 для своей регистрации и защищённых
операций. Подготовьте PostgreSQL 18.7 с принятой миграцией IAM и выделенным
логином с правами `hp_iam_app`. Миграция запускается отдельно своим логином.
При отсутствии `postgres.max_connections` предел пула равен 5. Настраиваемый
предел — от 1 до 10 соединений.

Соберите и запустите процесс из чистой рабочей копии на закреплённом коммите с Go 1.27.2.

```sh
cd services/iam
go build -buildvcs=true -o /tmp/hitpipe-iam ./cmd/iam
/tmp/hitpipe-iam -config /absolute/path/iam.json
```

Путь можно также задать через `HITPIPE_IAM_CONFIG`. Файл задаёт следующие параметры.

- `build_revision` — фактический 40-символьный SHA сборки. Команда сверяет
  его с VCS-метаданными бинарника. Для чистого экспортированного дерева
  сборщик передаёт проверенный SHA через `-X main.buildRevision=<sha>` при
  `-buildvcs=false`.
- `business` и `ops` — отдельные частные IP-адреса с портами 8443 и 9444,
  `certificate_file`, `key_file`, `client_ca_file`; EDGE-клиенты задаются
  в `business.edge_peers`, OPS-клиенты — в `ops.peers`. Сертификат клиента
  связывается с точными `dns_name` и `certificate_fingerprint`
  (`sha256:` и 64 шестнадцатеричных символа DER-хеша).
- `runtime.local` и `runtime.peers` — точное поколение, boot ID, идентификатор
  и отпечаток каждого IAM и разрешённого сервисного экземпляра. Списки
  привязки включают локальный IAM и конкретный BFF.
- `postgres.dsn_file`, `oidc.client_secret_file` и серверные `key_file` —
  абсолютные пути к отдельным файлам владельца. В `oidc` также задаются
  `issuer`, `authorization_endpoint`, `token_endpoint`, `jwks_uri`,
  `redirect_uri` с точным путём `/auth/callback`, `client_id`, `ca_file`,
  `success_path`, `session_absolute_lifetime` и `session_idle_lifetime`.
  PostgreSQL использует проверку имени TLS `verify-full`. Локальный
  незашифрованный TCP допустим только при явном DSN на loopback.
- `profile_root` — частный каталог файлов профиля IAM.

| Слушатель | Маршрут | Допустимая идентичность |
| --- | --- | --- |
| 8443 | GET `/auth/login`, GET `/auth/callback` | EDGE |
| 8443 | GET `/api/v1/profile` | BFF и текущая сохранённая сессия |
| 8443 | POST `/internal/v1/authorize`, POST `/internal/v1/runtime/register` | IAM, Intake, Processing, Delivery, BFF или AI из списка Runtime |
| 9444 | GET `/internal/v1/health/iam` | Только OPS |

Оба слушателя требуют TLS 1.3 и проверяют клиентский сертификат.
OPS получает `LIVE` только когда шлюз открыт и неизменившаяся регистрация
этой загрузки подтверждается в PostgreSQL. Иначе OPS получает `CLOSED`.
Это технический сигнал об экземпляре. Действительность сессии, право на
действие и готовность подключений определяются своими проверками.

При неверных настройках или TLS-материалах команда прекращает запуск.
При недоступной базе регистрация остаётся закрытой, попытки ограничены
по времени. При перезапуске требуется допустимая новая регистрация и
авторитетно подтверждённая изоляция прежней загрузки, если она ещё числится
открытой. Завершение через `SIGTERM` отменяет работу, останавливает оба
слушателя и закрывает пул перед выходом процесса.

Приложение получает независимые часы и действительные источники разрешения
выпуска сессии и доказательства ресурса через `RunWithAuthorities`. Штатная
команда со своими файловыми настройками и без этих источников сохраняет
закрытые пользовательские операции. На стенде текущие факты, регистрации,
сессии и файлы проверяются реально, а внешние допуски явно ограничены
тестовыми идентичностями.

Команда локальной проверки выполняется из корня репозитория.

```sh
python3 services/iam/tools/check_iam_process.py --evidence-dir /tmp/hit138-check
```

Драйвер поднимает одноразовую PostgreSQL 18.7 из закреплённого образа,
проверяет реальный дочерний процесс и TLS-запросы, затем удаляет временную
базу и сеть. Используйте новый пустой каталог для каждого протокола.

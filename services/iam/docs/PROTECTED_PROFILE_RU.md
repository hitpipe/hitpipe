# HIT-85 — защищённое чтение своего профиля

Добавлен приватный обработчик IAM `GET /api/v1/profile`. BFF предъявляет свой
проверенный клиентский сертификат и внутренний заголовок `X-HitPipe-Session`.
IAM находит текущую сохранённую сессию, определяет её владельца, читает только его
профиль и возвращает ровно `user_id`, `display_name`, `timezone`, `revision`.
Идентификатор пользователя берётся из базы IAM. Значения роли, пользователя,
рабочего пространства или сертификата из браузерных заголовков прав не дают.

Профиль здесь принадлежит пользователю целиком. Для его чтения не создаётся
несуществующее разрешение рабочего пространства или членство. Существующий
`authorizeaction.Execute` обслуживает действия в рабочем пространстве и потому
не вызывается с выдуманным workspace. Переиспользованы ядро проверки сессий,
`AuthenticateSession`, `sessionlookup.Reference`, типы runtime и проверка SQL-роли
из HIT-84. Правила ролей не скопированы в новый независимый механизм.

## Как проходит запрос

1. HTTP-адаптер допускает только TLS 1.3 с проверенной цепочкой клиентского
   сертификата. Точное DNS SAN и SHA-256 отпечаток должны совпасть с явно заданной
   привязкой BFF. Самоподписанный, просроченный, чужой сертификат и обычный HTTP
   прав не дают. Проверка повторяется перед началом успешного ответа.
2. Исходный непрозрачный секрет сессии превращается существующим `Reference` в
   хеш. В SQL и допуск передаётся хеш, содержимое секрета не журналируется.
3. Обязательный `getprofile.Gate` допускает ограниченную критическую операцию и
   удерживается до фактического начала ответа. Неизвестный допуск, закрытый
   процесс или недоступный порт завершаются отказом. Разрешающего адаптера по
   умолчанию нет. Контекст операции ограничен двумя секундами.
4. В свежей read-only транзакции PostgreSQL читаются сессия, её principal,
   указатель и digest профиля, текущий runtime BFF и отзывы этой сессии. Сессия
   проверяется существующим ядром с явно переданными доверенными часами.
5. Файловый адаптер открывает только разрешённый файл, сверяет точные байты с
   digest и строго разбирает структуру профиля. При отсутствующем файле,
   недоступной базе, повреждённом digest или данных успешного ответа нет.
6. После файлового чтения IAM заново читает текущие факты. Смена сессии, владельца,
   epoch, runtime, ref или digest не допускает ответ по прежним данным. Отзыв
   `SESSION` учитывается по точному session ID, в том числе при отсутствующем или
   чужом workspace у записи отзыва. Повторное подтверждение фактов допуском и
   проверка времени происходят перед единственным вызовом начала HTTP-ответа.

HTTP-адаптер устанавливает write deadline в том же ограниченном контексте и
принудительно начинает отправку через Flush, пока допуск ещё удерживается.
Транспорт без поддержки deadline/Flush не допускается; на постоянном соединении
срок сертификата повторно проверяется перед ответом.

Успешный ответ не обновляет время жизни сессии. Cookies браузера здесь не
заменяют внутренний заголовок BFF; запись профиля, CSRF для записывающих методов,
вход, выход и продление сессии не добавляются. Ошибки содержат безопасный
серверный `request_id`, сообщения и коды OAS. Ответы имеют `Cache-Control:
no-store`. После начала ответа повторный ответ или повтор операции запрещены:
уже отправленные байты невозможно отменить.

## Частный формат файлового адаптера

Принятая SQL-схема задаёт UUID `profile_content_ref` и текстовый
`profile_digest`, но не навязывает кодировку файлов. Для этой реализации выбраны:

- файл `<profile_content_ref>.json`, ref — канонический UUID в нижнем регистре;
- полный объект Profile без дополнительных полей; `user_id` обязан совпасть с
  текущим владельцем из SQL, а в ответ подставляется канонический server ID;
- digest `sha256:` и 64 шестнадцатеричных символа в нижнем регистре, SHA-256
  точных байтов файла, включая пробелы;
- UTF-8, все четыре поля обязательны; повторные и неизвестные поля, `null`,
  лишний JSON, некорректный Unicode и revision за пределами 1…9007199254740991
  отвергаются. Длины имени 1…120 и timezone 1…80 считаются в символах. Новый
  запрет произвольной timezone в пользу только IANA не вводится;
- до 32 KiB на файл — локальная граница памяти, не срок хранения продукта.

Каталог принадлежит пользователю процесса и имеет права `0700`, файл — `0600`.
Каждый компонент пути каталога открывается без перехода по символическим
ссылкам. Удерживается файловый дескриптор каталога; путь из запроса не собирается.
Только обычный файл с одной жёсткой ссылкой; symlink, FIFO, каталог вместо файла,
обход пути и открытые права доступа дают отказ. Права проверяются и при чтении.
Общего кэша и возврата старой копии после ошибки нет. Содержимое, секрет сессии,
контактные сведения и сырые ошибки ОС/SQL в диагностике не выводятся.

Это соглашение приватного адаптера, а не изменение formal SQL/OAS. Пишущий
адаптер должен использовать те же encoding/digest и принятую долговечную
публикацию содержимого. Запись через fsync/rename, очистка и координатор удаления
здесь не реализуются. Для профиля не выдумывается отсутствующий в источниках TTL.

## Подключение и проверка

HTTP `profile.New` требует готовый прикладной Service и явный Config с SAN и
привязкой BFF. `profile.TLSConfig` принимает серверный сертификат и доверенные CA;
секреты не генерируются и не сохраняются в исходниках. Прикладной
`getprofile.New` требует все порты: SessionLookup, ReferenceDeriver, Clock,
Reader, Content, Gate. PostgreSQL Reader заимствует ограниченный IAM app pool;
`profilefiles.Reader` владеет дескриптором каталога и закрывается через `Close`.
Ни один обязательный порт не заменяется разрешающей заглушкой в рабочем коде.

Из корня репозитория, Linux, Docker, Go 1.27.2:

```sh
python3 services/iam/tools/check_profile.py --evidence-dir /tmp/hit85-check
```

Команда использует отдельную PostgreSQL 18.7 с закреплённым образом, временные
роли и данные, сертификаты в памяти и owner-файлы во временных каталогах.
Проверяются миграции, права, актуальность SQL-фактов, настоящий HTTPS/mTLS,
ошибки сертификата/сессии/контента, отзыв во время чтения, отмена и недоступность.
Затем выполняются integration `-race`, `vet`, `build`. Обязательные PostgreSQL и
HTTPS+PostgreSQL+файл тесты не могут незаметно превратиться в SKIP. Старые команды
проверки схемы и SessionLookup также включают их при наличии реализации.

## Что требуется при дальнейшем запуске сервера

Эта задача даёт обработчик и проверенную локальную композицию. Она не запускает
рабочий IAM, не подключает Keycloak, BFF или браузер и не поставляет общий
координатор HIT-69. Настоящие доверенные часы, runtime authority и общий допуск
должны быть переданы при подключении. В тестах допуск управляемый и проверяет
границу начала ответа; это не доказательство работы распределённого gate.
Рабочий слушатель обязан быть приватным по архитектуре, иметь ограниченные
таймауты и установленную привязку BFF; тестовый loopback listener им не является.
Нельзя подключать этот обработчик с «всегда разрешать» вместо обязательного порта.

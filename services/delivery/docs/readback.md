# HIT-93 · Проверка известной задачи и публикация наблюдения

Delivery принимает POST /internal/v1/delivery-query от Processing через
существующий TLS 1.3 listener с проверкой клиентского сертификата и SAN.
Запрос указывает рабочую область, дело, линию эффекта, epoch и срок.
При наличии native task ID он должен точно совпасть с уже сохранённым ID.
Хранилище проверяет существующую квитанцию, попытку, линию, установленное
соединение и частное содержимое HIT-91. Независимый источник полномочий
подтверждает ту же конфигурацию и назначение.

Запрос к ClickUp использует GET /api/v2/task/{task_id} с одной проверенной
TLS-сессией и общим лимитом ключа. ClickUp остаётся источником фактического
workspace, List, исполнителей и названия. Числовые идентификаторы читаются без
плавающей точки. Доказательство содержит только существенный блок передачи,
время и источник чтения. Внешний текст вне блока не переносится в SQL или
в журнал. Сравнение адаптирует чистый код HIT-59 к принятой форме v1:
многострочный контекст сохраняется, отдельные признаки имеют значения
true, false или null. Проверка возвращает RESULT_VERIFIED только при совпадении
всех обязательных признаков. Недоступные, повреждённые и неоднозначные ответы
сохраняют неполное знание.

Файл наблюдения и файл сообщения записываются с проверкой целостности до
единой SQL-транзакции, которая сохраняет наблюдение, ссылку на доказательство
и запись очереди отправки. Срок файлов ограничен исходным сроком поручения.
Повторное чтение создаёт отдельное наблюдение. Выполненная попытка создания
сохраняет исходный ID и необратимую отметку возможного эффекта.

Обработчик очереди отправляет TaskObservation в Processing по mTLS. После потери
ответа следующий допущенный запуск читает тот же файл с тем же message_id и
digest. Квитанция с правильным ID завершает запись очереди. Повтор ограничен
арендой, числом попыток и сроком содержимого. Экспоненциальная пауза со
случайным разбросом записывается в очередь и индекс заданий. При HTTP 429 или
503 корректный Retry-After задаёт минимальную паузу. Если следующая попытка
пришлась бы на истечение срока содержимого или позже, запись переходит в HELD.
Рабочие полномочия, ключи,
регистрация runtime и развертывание предоставляются отдельно.

Проверка из services/delivery: **pwsh -NoProfile -File tests/run_hit91.ps1**.
Стенд использует PostgreSQL 18.7 Alpine, Go 1.27.2, отдельные роли, частный
каталог и два управляемых HTTPS-узла. Проверки нового кода и регрессии HIT-91
и HIT-92 проходят в одной изолированной сети. Реальный ClickUp не вызывается.
Справка по внешней операции находится в [ClickUp Get Task](https://developer.clickup.com/reference/gettask).

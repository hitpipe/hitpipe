# HIT-92 · Одна попытка создания задачи

Обработчик принимает идентификаторы рабочей области и сохранённой попытки.
Он читает квитанцию HIT-91, строки попытки и линии эффекта, а также файл
содержимого по проверенной ссылке. Точные List, assignee, workspace назначения
и digest конфигурации сохраняются при приёме поручения, внутри частного файла.
Ранее сохранённый файл без этих полей удерживается до появления проверенного
поручения с полным назначением. Повтор квитанции сам по себе файл не меняет.

Перед сетевым запросом обработчик фиксирует состояние DISPATCHING и
необратимую отметку попытки в PostgreSQL. После TLS-рукопожатия он проверяет
текущую область, epoch, сроки и общий лимит учётных данных, затем фиксирует
границу возможного сетевого старта. Запрос уходит после завершения SQL-транзакции.
Блокировка допуска освобождается после записи запроса в соединение. Чтение
ответа выполняется отдельно.

HTTPS-транспорт открывает новое TLS 1.3 соединение для одного HTTP/1.1 POST.
Он отправляет имя, сохранённый текст и идентификатор исполнителя на точный
List. Идентификаторы сохраняются как строки. ClickUp получает assignee как
целое число в проверенном диапазоне int64, без преобразования через float.
Маршрут, имя TLS и порт задаются транспортом. Перенаправления и повторные
запросы отсутствуют. Рабочий транспорт имеет фиксированное назначение
api.clickup.com. Тесты используют только локальный сервер с собственной CA.

Ответ со строгим JSON и непустым native task ID записывает TARGET_ID_OBSERVED
и переводит линию в RESULT_ID_OBSERVED. Оборванный ответ, таймаут, неожиданный
статус или повреждённый ответ сохраняют AMBIGUOUS. Падение после фиксации
DISPATCHING оставляет стойкую отметку, которая переживает новый процесс.
KNOWN_NO_EFFECT в этой реализации не выдаётся, автоматическая повторная
попытка отсутствует. Сохранённый ID используется для последующей проверки
в отдельной задаче.

Источники полномочий, допуска runtime, ключей и окна общего лимита должен
предоставить владелец сборки. Без них отправка недоступна. Полный распределённый
отзыв, доступ к рабочему ClickUp и развёртывание остаются отдельной работой.

Прогон из services/delivery: **pwsh -NoProfile -File tests/run_hit91.ps1**.
Стенд использует точную миграцию HIT-70, роли приложения и обработчика,
PostgreSQL 18.7 Alpine и Go 1.27.2 на linux/amd64. После загрузки зависимостей
проверки выполняются в частной сети без опубликованных портов. Прогон включает
новые тесты и регрессию HIT-91, гонки и go vet.

# HIT-94 — исходная линия и гипотеза

Рабочий baseline — принятый HIT-93, вершина PR #99
`0914c3cbdaa82b01b15231d39ceffcec983eea7d`, исходники
`f8498a4d4eccfd537149ecff17b9d0936e8f1bb2`. PR #99 открыт и служит базой
ответвления. До измерения добавлен только стенд; код чтения baseline не менялся.
HIT-93 создаёт новый TCP/TLS 1.3 для каждого GET и закрывает его после чтения.
TLS-подключение, создание соединения и закрытие повторяются даже для готового
предыдущего ответа с однозначной границей. Проверяемая гипотеза — переиспользование
ограниченного числа уже проверенных соединений уменьшит число новых TCP
соединений на успешных чтениях при прежних проверках допуска и результата.

Одинаковый стенд запускает реальный QueryService с TargetReader/VerifyTarget,
синтетическим ClickUp HTTPS, PostgreSQL 18.7 и файловым хранилищем наблюдений.
На каждый сценарий пять независимых повторов, новый сервер и отдельная синтетическая
область/квота. В каждом повторе 16 GET прогрева и 96 измеряемых GET. Сценарии —
успешное чтение с concurrency 1 и 4, 429 с concurrency 4. Одинаковы атрибуты,
размеры ограничений, SQL и стендовые данные. Каждый GET проверяет результат
TaskObservation и счётчик физических GET. Меряем полную задержку QueryService,
пропускную способность и новые TCP соединения после прогрева. p50/p95 считаются
по nearest rank. TCP подключения прогрева показаны отдельно.

Baseline не имеет idle pool. В обеих версиях запрос ограничен 8 секундами
или сроком DeliveryQuery, шаг допуска/старта — 2 секундами, ожидание ответа —
4 секундами, запись наблюдения — 2 секундами, тело ответа — 64 КиБ.
Кандидат — отдельный read-only пул одного TLS origin с жёстким пределом
8 активных каналов, не более 4 простаивающих соединений, idle TTL 15 секунд.
Лимит стенда concurrency 4 и fixture quota отделены от продуктового бюджета.
В каждом вызове создаётся один GET под текущим epoch/actual-start gate.
Неподходящие для reuse ответы и ошибки закрывают соединение без повторной отправки.

Из `services/delivery` выполнить `pwsh -NoProfile -File tests/run_hit91.ps1 -ReadbackBenchmark`
на неизменном baseline и кандидате. Для correctness отдельно выполнить
`pwsh -NoProfile -File tests/run_hit91.ps1`. CPU, доступная память, Linux kernel,
Go и digest образов записываются в протокол запуска. Сравниваются все повторения.

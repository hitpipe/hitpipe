# Platform: локальная защита начала работы

`startgate` — библиотека для **одного процесса**. Она упорядочивает фактическое
начало защищённого действия и применение отзыва доступа. Пакет подготовлен в HIT-69;
ни один действующий сервис пока его не вызывает.

## Поведение

- Новый `Gate` закрыт. До текущего снимка состояния никакое действие не начинается.
- Снимок принимается только для точных `runtime_id`, `boot_id` и `generation`.
  Старая редакция и противоречащая повторная доставка отклоняются.
- `Start` проверяет все переданные области доступа под одной блокировкой и вызывает
  короткую функцию **фактического начала действия, ещё удерживая блокировку**.
  Отдельное разрешение на будущий запуск не выдаётся.
- `ApplyBarrier` дожидается выхода прежней секции начала, сохраняет запрет и только
  затем возвращает подтверждение. После него новое действие отозванного субъекта
  не начнётся. Уже начатая операция может завершиться позднее.
- Известный запрет сохраняется на всё время жизни этого объекта. Более высокая
  эпоха и новый снимок, в котором запрет пропущен, его не снимают. Повторное
  предоставление доступа в этот элемент не входит.
- Повтор того же барьера возвращает прежнее подтверждение с прежним временем.
  Изменение команды под прежним идентификатором отклоняется. Истёкший срок новой
  команды либо отмена ожидания не дают положительного подтверждения.

Опоздавший действительный барьер при доступной блокировке всё равно сохраняет
запрет, но не получает нового положительного подтверждения. Если блокировка не
получена, процесс удерживает все последующие секции начала закрытыми. Уже допущенная
секция может ещё пересечь фактическую границу начала: положительного подтверждения
барьера в этом случае нет. Это удержание не снимается
последующим OPEN-снимком; требуется новый объект процесса и свежая регистрация.
Такой консервативный отказ сохраняет безопасность при неизвестном применении
барьера, но сам по себе не означает успешный отзыв в распределённой системе.

Снимок содержит **запреты**, а не полномочия. В `StartRequest` владелец отдельно
передаёт проверенный разрешённый контекст: явное `Allowed`, отсутствие ожидающего
отзыва, актуальные эпохи и все применимые субъекты сессии, участника, подключения
и рабочего пространства. Пакет не получает эти сведения из IAM и не умеет
определить, какие бизнес-ресурсы относятся к запросу. Отсутствующее разрешение,
пустой набор субъектов и некорректные значения не открывают доступ.

Глобальный запрет с `WorkspaceID == nil` действует на тот же субъект и область
во всех рабочих пространствах. Пустая строка вместо `nil` — ошибочный UUID.

## Как использовать при будущем подключении

Создать один объект через `New(Identity)` на весь действительный процесс. Этот
же объект обязаны использовать все защищённые SQL-чтения, начала ответов и внешних
запросов, а также обработчик барьера. При новом запуске создаётся новый объект
с новой идентичностью и закрытым состоянием; сохранённый старый снимок не открывает
новый запуск. Текущее решение не разделяет память между отдельными процессами.

Функция внутри `Start` должна синхронно пересечь настоящую границу начала работы.
Она не должна только ставить будущий запрос в очередь или создавать отложенный
непроверяемый запуск. Длительное продолжение уже начатой операции выполняется
после выхода из секции. Ошибка функции не доказывает, что внешняя запись не началась;
автоматически повторять такую запись на основании одной ошибки нельзя.

Функция должна быть короткой, соблюдать переданный `context` и принятый предел
критической секции не более двух секунд. Повторный вход в тот же `Gate` запрещён.
Go не позволяет безопасно принудительно остановить произвольную функцию: если она
игнорирует отмену, блокировку нельзя отпустить и выдать ложное подтверждение отзыва.
Ожидающий барьер тогда завершается без подтверждения. Соблюдение временного предела
самим транспортом требует отдельного подключения и проверки.

Структуры пакета — внутренние типы библиотеки, **не готовый HTTP-интерфейс**.
Адаптер обязан отдельно обеспечить точные плоские поля, required/null/unknown-field
проверки, доверенную регистрацию и mTLS принятой OpenAPI-схемы. Здесь таких
обработчиков, координатора, сетевой или базовой изоляции нет.

## Проверка

Принятый набор сборки — Go 1.27.2, для проверки гонок также нужен C-компилятор.
Внешних зависимостей у этого модуля нет. Из корня репозитория:

```sh
python3 services/platform/tools/check_start_gate.py --evidence-dir /tmp/hitpipe-platform-checks
```

Скрипт выполняет обычные тесты, десять повторов с `-race`, `go vet` и сборку.
Сохраняет команды, коды завершения, среду, SHA файлов и исходные протоколы.
Он проверяет неизменность исходников во время прогона. Отдельный GitHub Actions
`platform-start-gate` запускает те же проверки на версии из запроса изменений.

Контролируемая функция начала и синтетические сведения о полномочиях в тестах
подтверждают локальное упорядочивание. Они **не подтверждают** полный отзыв между
сервисами, действительную изоляцию старого процесса от сети и базы, подключение
реального транспорта или соблюдение пяти секунд в развёрнутой системе.

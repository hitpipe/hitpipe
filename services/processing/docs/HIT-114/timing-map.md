# Источники времени и наблюдаемые исходы HIT-114

| Период или ситуация | Источник и итог |
| --- | --- |
| `WORKING` | Неизменяемый `episodes.started_at/deadline_at` открытого эпизода. Срок допустим в границах 300 с от начала эпизода. Запись входа в состояние и владелец файла истории связывают episode, case и оригинальную lineage. |
| Истёкший `WORKING` | `CASE_WORKING_DEADLINE_REACHED`, состояние `UNKNOWN`. Эпизод завершён, активные попытки транспортной отправки удержаны. Существующие lineage, fence, native ID, знание об исходе и записанный ACK сохраняются. |
| Непрерывный `WAITING_DATA` | Последний действительный переход в состояние из другого состояния, время и связанный файл истории. Самопереходы, повторы сигналов и перезапуски не используются как минуты отсчёта. |
| Истёкший `WAITING_DATA` | `CASE_WAITING_DATA_DEADLINE_REACHED`, состояние `ATTENTION`. Порог 24 часа, проверенное окно обработки — до 5 минут после порога. |
| Время или доказательство отсутствуют | `CASE_TIMER_HISTORY_MISSING`, `CASE_TIMER_EPISODE_MISSING`. Таймер удержан с точной причиной. |
| Несогласованные данные | `CASE_TIMER_HISTORY_INVALID`, `CASE_TIMER_EPISODE_INVALID`. Несовместимые данные и повреждённый файл не порождают дедлайн. Будущее время отображается отдельной ошибкой чтения. |
| Истёк файл | `CASE_TIMER_HISTORY_EXPIRED`. Деталь показывает удержание, история сохраняет минимальные записи по HIT-95. |
| Выполнение | Бизнес-время поступает от часов Processing, управляемых в точных тестах. Аренда сравнивается с временем PostgreSQL. Повторная передача задачи, время boot и время получения дубля не задают новый срок. |
| Гонка | Сверка текущего состояния и ревизии под SQL-блокировкой. Новое финансовое решение или наблюдение, принятые раньше записи таймера, сохраняют свой результат. |

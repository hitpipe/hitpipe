# HIT-114. Предельные сроки дела Processing

Codex по делегации Тимофея Патрушева / Tim1hik. Контракт редакции 1. [Карточка Jira](https://hitpipe.atlassian.net/browse/HIT-114) · [PR №78](https://github.com/hitpipe/hitpipe/pull/78).

**WORKING.** Источник срока — открытый эпизод с неизменяемыми `started_at` и `deadline_at`, который связан с сохранённым входом в `WORKING` и первоначальным `DeliveryIntent`. На принятой границе обработка становится `UNKNOWN`. Установленное знание, прежний ID задачи, lineage и fence сохраняются. Новые старты исходящей записи удерживаются, а уже сохранённый транспортный ACK остаётся в журнале. Поздний таймер с устаревшей ревизией уступает новому решению или `TaskObservation` HIT-99.

**WAITING_DATA.** Начало непрерывного периода берётся из последнего действительного входа в это состояние. Повтор сигнала и запись `WAITING_DATA → WAITING_DATA` не сдвигают его. Через 24 часа непрерывного ожидания дело становится `ATTENTION` с сохранённой причиной. Проверен переход в пределах следующих пяти минут и отдельный переход на самой границе.

**Диагностика.** Нет открытого эпизода, история отсутствует, просрочена или не проходит проверку владельца и целостности — действие удерживается, конкретная причина видна в чтении дела. Если время истории находится в будущем, оба API возвращают точную ошибку времени, а воркер сохраняет ограниченное ожидание без выдуманного времени записи. Истёкшая история отдаёт минимальные записи в соответствии с HIT-95. Повреждённые данные могут сделать историю недоступной.

Воркер индексирует до пяти записей за проход в пределах workspace и владельца. В `job_index` только ID задания, workspace, вид, время готовности и метаданные аренды. PostgreSQL с RLS и короткой десятисекундной арендой проверяет текущую ревизию, исходные времена и действительность lease. В одной транзакции сохраняются новое состояние или диагноз, минимальная история, ссылки на истекающее содержимое и одно уведомление на пару дело и причина. Подробности находятся в собственных файлах Processing. Временная ошибка SQL оставляет работу доступной после окончания аренды. Обработка `DRAINING` операции остаётся в существующем HIT-103.

| 7. Ограничения воркера | Блокировка `SKIP LOCKED`, две работы при лимите два, один владелец на запись, отклонение отмены, потеря и повторный захват аренды, откат реального SQL. |

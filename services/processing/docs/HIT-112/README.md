# HIT-112. Фоновое продвижение принятых дел

Codex по делегации Тимофея Патрушева / Tim1hik. Контракт редакции 1. [Jira](https://hitpipe.atlassian.net/browse/HIT-112) · [PR №73](https://github.com/hitpipe/hitpipe/pull/73).

HTTP 202 возвращается после commit дела, inbox и начальной истории. Сохранённая пара дело/inbox даёт worker устойчивый вход после перезапуска. Роль `hp_processing_worker` восстанавливает метаданные в `job_index`. Запись содержит идентификаторы дела и workspace, вид работы `CASE_PREPARE`, время готовности, токен и срок аренды. HTTP-роль сохраняет прежние права.

На каждом проходе worker индексирует не более пяти кандидатов и захватывает не более одного дела на workspace. Захват использует `FOR UPDATE SKIP LOCKED` и аренду 10 с. Кандидат, дело, операция и последнее применённое событие проверяются в своей области RLS. В момент фактического старта SourceFacts worker снова проверяет право чтения, эпоху, открытый HIT-69, действующую аренду, принятые привязки и срок. Сетевой запрос имеет предел 2 с и при необходимости ограничен более ранними сроками аренды и эпизода. SQL закрывается до сетевого I/O.

Решение по оплате принимает существующий HIT-79 с фактами HIT-77. Время оценки считывается после чтения, когда факты уже получены. При commit под блокировкой проверяются токен, срок, редакции дела и операции, конфигурация, закреплённый источник и последнее событие. Если новый сигнал поступил во время чтения, прежний результат отклоняется. Изменения дела, история, эпизод, `DeliveryIntent` при допустимой оплате и снятие `CASE_PREPARE` фиксируются одной транзакцией. При откате открытая работа восстанавливается после аренды. При потерянном ответе успешного commit следующий проход видит сохранённый результат и ту же lineage.

Неоплата, неполные факты и отказ чтения сохраняют `WAITING_DATA`. Для новой попытки требуется новое принятое событие той же Session. Точный повтор сообщения возвращает прежний ACK. Сохраняются исходные case/config/граница активации. Sender HIT-98 использует единственный outbox. Его Receipt переводит outbox в `ACKED`. В проверенном сценарии дело остаётся `WORKING`. Для `CONFIRMED` действует отдельный путь наблюдения HIT-99.

| Критерий | Фактическая проверка |
| --- | --- |
| 1. Реальные версии и reuse | Собственный diff от `49229e1` затрагивает Processing и артефакт результата. Admission, ядро, SourceFacts Decode, sender, DDL/OAS и общие CI сохранены. HIT-111 и его предшественники зафиксированы с фактическим состоянием, отдельно от main. |
| 2. Durable admission и restart | Реальный HTTP 202 и точный повтор прежнего receipt через перезапуск. Срыв commit admission не возвращает ACK, не создаёт дело/inbox и не порождает индекс. |
| 3. Claim, fencing, RLS | Два параллельных worker-захвата дают одного владельца. После истечения срока второй процесс может продолжить ту же работу. Старый токен и чужой workspace отклоняются. HTTP-роль не получала прав индекса. Отдельное соединение получает блокировку `NOWAIT` во время чтения фактов. |
| 4. Допуск, привязки и срок | TLS с проверкой цепочки и SAN, IAM с epoch, защита фактического старта. Проверены неизвестная привязка, чужой workspace, снятая выбранная конфигурация, истёкший эпизод, CLOSED и барьер в TLS-рукопожатии. |
| 5. Оплата и состояние | На работающем процессе проверены свежий ответ, неполные факты, HTTP 503 источника, неоплата, поздняя оплата той же Session, старая Session, ровная граница первой активации. Ровно одна lineage, один эпизод и один Receipt. Повтор не запускает новый запрос. |
| 6. PAUSE и отзыв | PAUSE во время уже начатого чтения блокирует commit нового intent и новая приёмка в DRAINING закрыта. Регрессии HIT-111/HIT-103 проверяют DRAINING → PAUSED, resume, сохранение исходной границы и действительного ответа уже начатой доставки. Общий барьер отзыва запрещает HTTP SourceFacts после ACK, даже если TLS-рукопожатие уже началось. |
| 7. Сбои и ограничение повторов | SIGKILL при чтении и перезапуск того же бинарника, смена владельца по истечении аренды, реальный откат commit и потерянный ответ после реального commit. Технический abort допускает повтор после истечения аренды. Зафиксированная неизвестность или неоплата ждут нового входного события. |
| 8. Исполняемая проверка | На чистом коде `0f710a6682d15b437f847376b348947cb4757c7c` прошли полный набор PostgreSQL 18.7, два процесса HTTPS/mTLS, Go 1.27.2 `race`, `vet`, `build`. GitHub CI дал `6/6 SUCCESS`. Команды, время, exit codes, версии, SHA и исходные журналы приложены. |

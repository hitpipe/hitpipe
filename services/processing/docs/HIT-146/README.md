# HIT-146. Отзыв прав Processing с настоящим IAM

Codex по делегации Тимофея Патрушева (Tim1hik). [Задача](https://hitpipe.atlassian.net/browse/HIT-146) · [Draft PR №90](https://github.com/hitpipe/hitpipe/pull/90).

На изолированном TEST-стенде прошли четыре критерия. Processing `717c954fca4f06f165074a8688f0e94a31b398e7`, IAM `e1be0c1a0be577a3626a3e120707b3aeeb579c6f` из [Draft PR №92](https://github.com/hitpipe/hitpipe/pull/92), PostgreSQL 18.7 и Go 1.27.2. Предыдущая блокировка и её журналы сохранены [в истории](https://github.com/hitpipe/hitpipe/blob/4ce06f30ef8cbd786d7024f0fe2ff81cc6dd8ff7/services/processing/docs/HIT-146/README.md).

| Критерий | Фактический результат |
| --- | --- |
| Перезапуск | Неподготовленный запуск получил 403 от IAM. После перезапуска согласованный boot получил SYNCING и оставался CLOSED с бизнес-ответом 503. Свежий OPEN открыл чтение истории с 200. Снимок старого поколения отвергнут, старая регистрация получила 403, чужой principal отвергнут при mTLS. Повтор файловой привязки остановил запуск. |
| Отзыв | После реальных ACK IAM и Processing с точной идентичностью, эпохой 8 и подтверждённым выходом из старых секций повтор чтения истории того же дела получил 403. Новый HTTP-старт Delivery на старой эпохе не произошёл. |
| Удерживаемый запрос | Первый HTTP-старт состоялся до барьера. После тайм-аута outbox остался CLAIMED с одной попыткой и одним вызовом Delivery. Записи ACKED и повтора не было. Отдельный отзыв с отсутствующим Processing остался PENDING, а после срока перешёл в INCIDENT без EFFECTIVE. |
| Время | Действительный отзыв стал EFFECTIVE через 15,044 мс при лимите 5000 мс. В отрицательном сценарии намеренно отсутствовал ACK Processing. INCIDENT наблюдался через 5098 мс, превышение зафиксировано, эффективный отзыв не подтверждён. |

Доверенный файл заранее связывает runtime, поколение, boot и SHA-256 исходящего TLS-сертификата. Защищённую работу по-прежнему открывает только свежий снимок от IAM. Для control-портов закреплены отдельные серверные сертификаты. Тестовый ввод — синтетические учётные записи и привязки в PostgreSQL, PKI, controlled Delivery и Intake. IAM выдавал разрешения из своей базы и проверял предъявленную сессию и принятую TEST-конфигурацию. Данные запросов, сессии и ключи в пакет не включены. ClickUp и Stripe находятся вне этого прогона.

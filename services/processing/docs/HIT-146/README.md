# HIT-146. Граница отзыва Processing с настоящим IAM

Codex по делегации Тимофея Патрушева (Tim1hik). [HIT-146](https://hitpipe.atlassian.net/browse/HIT-146) · [Draft PR №90](https://github.com/hitpipe/hitpipe/pull/90)

**Квалификация заблокирована на регистрации Processing.** На настоящих раздельных процессах с PostgreSQL 18.7 новый `boot_id` отклонён. При отдельно проверенной точной привязке настоящий IAM отвечает `200 / SYNCING`, включая повтор после перехода самого IAM в `OPEN`. Защищённый вызов Processing остаётся закрытым.

| Критерий | Фактический результат |
| --- | --- |
| Регистрация и перезапуск | Два разных boot ID реального Processing получили 403 от IAM в каждом прогоне. OPS Health 200/CLOSED, бизнес-запрос 503. Снимок предыдущего поколения отвергнут проверкой засова, запрос старого поколения получил 403, чужой principal отвергнут при mTLS. Свежий допуск Processing не достигнут. |
| До и после отзыва | Настоящий `authorizeAction` отвечает 403 удалённому runtime в SYNCING. Защищённый вызов до отзыва и настоящий ACK Processing не получены. Отсутствие старого старта **после ACK** не заявляется. |
| Удерживаемый запрос | В положительном сценарии запрос не мог стартовать. Подготовленный outbox в новом прогоне дал ноль обращений к управляемому Delivery. Отдельная отрицательная проверка установила PENDING, затем INCIDENT без EFFECTIVE и с двумя отсутствующими ACK. Эта проверка не подтверждает обработку уже начатого внешнего запроса при реальном отзыве. |
| Время и границы | В двух прогонах на одних SHA предел составил ровно 5000 мс с принятия. Фактическое наблюдение INCIDENT через 5091 и 5092 мс. Отзыв не подтверждён, превышение срока отражено в журнале как дефект квалификации. |

Точная версия Processing `ce317193244623c5a464a3014bb39f32875c1e98`. В стенде использованы настоящий IAM register/authorize, официальный координатор и настоящий Processing. Управляемые границы — синтетические учётные записи, запуск одобренного тестового намерения в API координатора внутри IAM-процесса, локальная PKI, Intake и Delivery. IAM resolver в этом стенде закрыт по умолчанию. IAM control listener для его собственного участника намеренно отсутствует в отрицательном тесте. Трасса показывает отказ Processing до защищённого старта и отказ подтверждения без полного набора ACK. Принятый IAM, API, DDL, роли, gate и бизнес-код Processing сохранены.

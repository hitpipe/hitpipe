## Поведение

Служебная команда обрабатывает один заранее выбранный workspace. PostgreSQL даёт время отсечения и подтверждает отдельно выданные полномочия `hp_processing_purge` с действующей RLS. До проверки файла просроченные неотправленные сообщения переводятся в `HELD` и фиксируются отдельным коммитом. Удаление повторно проверяет SQL-ссылки с блокировкой источников, метаданные и идентичность файла. Runtime держит общую блокировку каталога до остановки, служебная команда требует эксклюзивную. Закрытие процесса освобождает её для следующего запуска.

Обычное чтение по-прежнему отказывает в выдаче истёкшего тела. Физическое удаление выполняет отдельная команда. Минимальная история, identity, командные ключи, fence, lineage и знание о возможном внешнем эффекте сохраняются. Ни новая отправка, ни подтверждение доставки очисткой не создаются. [Карта объектов и сроков](retention-map.md), [инструкция запуска](RUN_RU.md).

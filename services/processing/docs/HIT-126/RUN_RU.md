# Запуск очистки Processing на локальном стенде

Команда выполняет одну партию для одного явно указанного workspace на изолированном стенде. Используются принадлежащий Processing каталог 0700 и соответствующая ему выделенная база PostgreSQL 18.7 с точной схемой Processing. Тестовый образ закреплён по digest `sha256:ece55f7868da684e400f82f1030a050718adbdd65c23aa500c486f6e2950dc0f`. Доступ к базе локальный через Unix-сокет или loopback, отдельной ролью `hp_processing_purge`. Пароль и DSN не передаются в аргументах и не печатаются в результате.

1. Сверить рабочую папку, выделенную тестовую базу и её volume, UUID тестового workspace и версию схемы. На стенде остановить все прежние процессы и держатели прежних версий Processing, дождаться завершения их SQL-транзакций. Обновлённые процессы и команда сами отказываются открывать уже занятую несовместимой блокировкой директорию.
2. Из корня репозитория выполнить `go -C services/processing build -o /tmp/processing-purge ./cmd/processing-purge` с Go 1.27.2.
3. Передать выданный стенду `HITPIPE_PURGE_DSN` через окружение и выполнить:

   ```sh
   /tmp/processing-purge --local-stand \
     --content-dir /absolute/path/to/isolated-processing-content \
     --workspace "$STAND_WORKSPACE_ID" --limit 100
   ```

4. Код 0 и JSON `{"held":...,"removed":...}` означают завершённую партию. Каждый счётчик ограничен `--limit` (1–1000). Если нужно, повторить до партии с нулевыми счётчиками. Команда читает каталог блоками, физически удаляет не более заданного числа файлов и ограничена общим таймаутом. Для большого каталога выход по таймауту требует осмотра стенда. Код 2 — неверный ввод. Код 1 — недоступная или занятая база/директория, отказ охраны либо неполная партия. Проверить локальные записи состояния и целостность volume, прежде чем повторять. На отказе команды уже закоммиченные удержания могут сохраниться, затем следующий запуск перечитает настоящее состояние. Файл повреждённого происхождения, symlink, hardlink или неизвестный срок не удаляется автоматически.

Офлайн-порядок рассчитан на один локальный файловый том с поддержкой `flock` и `fsync`. Старая версия Processing не участвует в этой блокировке. Выбирать volume и соответствующую базу необходимо вручную. Рабочие среды, рабочие секреты, чужие таблицы и сетевые файловые системы не входят в проверенный запуск.

Полное воспроизведение на новом одноразовом стенде (из корня):

```sh
PYTHONDONTWRITEBYTECODE=1 python3 services/processing/scripts/postgres/verify_purge.py \
  --output /absolute/path/to/new-log-dir --go /absolute/path/to/go1.27.2/bin/go
```

Вывод отдельного запуска включает Go race/vet/build на машине запуска, Linux-бинарники без race внутри изолированного PostgreSQL 18.7, точные команды, exit codes и SHA артефактов.

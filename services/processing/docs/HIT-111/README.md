# HIT-111. Исполняемый сервис Processing

Выполнил Codex по делегации Тимофея Патрушева / Tim1hik. Контракт HIT-111, редакция 1. [Jira](https://hitpipe.atlassian.net/browse/HIT-111) · [PR №72](https://github.com/hitpipe/hitpipe/pull/72).

`cmd/processing` собирает уже проверенные обработчики, свою PostgreSQL 18.7, файлы и отправщик в один процесс. `registerRuntime` открывает единственный объект HIT-69 после снимка для точного `runtime_id/boot_id/generation`. IAM barrier, обработчики, исходящий отправщик и фабрика SourceFacts обращаются к этому объекту. Публикация защищённого HTTP-ответа сбрасывает буфер net/http внутри секции фактического старта. Подключённые адаптеры по-прежнему проверяют актуальность решения и устойчивый исход SQL независимо от порядка сетевых ответов.

| Назначение | Состав и ограничение |
|---|---|
| Business 8443, BFF | Чтение дела и истории HIT-95, черновик/readiness/rehearsal HIT-100, активация с серверным `activation_preview` и окончательным digest HIT-102, pause/resume и снимок HIT-103. |
| Business 8443, Intake | `receiveNormalizedSignal` HIT-104 с проверкой установки и владельца, прежним admission HIT-78 и атомарным inbox/history. |
| Business 8443, Delivery | `applyTaskObservation` HIT-99 и привязка к собственным case/episode/lineage. |
| Control 9443 и health 9444 | IAM-only `applyRevocationBarrier` и OPS-only `healthProcessing`, строгие схемы OAS, TLS 1.3 с цепочкой и SAN. |
| Исходящий транспорт | IAM `registerRuntime` и `authorizeAction` по mTLS. Ready-to-use фабрика SourceFacts HIT-77 для будущего запуска обработки дела. Отправщик HIT-98 по утверждённому пути Delivery и прежнему журналу HIT-79. |
| Хранилище | Один узел и одна база Processing, разные роли приложения и воркера. Суммарный предел пула 10, в стенде 5. Один собственный каталог файлов. Миграции выполняются вне сервиса. |
| Shutdown | Запрет новых claim, завершение уже принятой работы в пределах окна, закрытие HTTPS, пула и файлов. Неподтверждённый сетевой старт не записывается как ACK. |

| 7. Завершение | Во время второго запроса Delivery послан SIGTERM. Процесс сохранил ACK после ответа на уже начатую отправку и завершился. В stdout/stderr проверено отсутствие содержимого конфигурации, сырых тел, сделанных на стенде токенов и закрытых ключей. |
| 8. Журналы и результаты | На чистом коде `b2e8230` записано 98 команд, включая ожидаемые SQL-отказы и проверку удаления стенда. Отдельно пройдены Go 1.27.2 `race`, `vet`, `build`, проверка и smoke Processing. Linux arm64 исполняемый и тестовый бинарники выполнены внутри закреплённого PostgreSQL-образа с CGO=0. |

Проверка проведена на управляемом стенде. В обычном режиме обязательные источники CSRF, привязок, поколения очереди и состава фоновой работы пока не подключены. Поэтому допуск остаётся CLOSED. Стенд даёт эти входы явно и только на loopback. IAM-запросы, TLS и данные Processing настоящие. Внешние Stripe/ClickUp, рабочий IAM и распределённый fencing остаются за пределами этого результата. SourceFacts подключён как фактическая готовая фабрика транспорта; HIT-111 не запускает финансовое продвижение нового дела и не добавляет отдельного маршрута для проверки SourceFacts. Его транспорт проверяется прежними применимыми тестами.

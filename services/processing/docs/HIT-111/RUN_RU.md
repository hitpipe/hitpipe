# Локальный запуск Processing

Команды из `services/processing` на Go 1.27.2.

```sh
sha=$(git rev-parse HEAD)
go build -ldflags "-X main.revision=$sha" -o /tmp/processing ./cmd/processing
/tmp/processing -config /absolute/path/processing.json -check-config
/tmp/processing -config /absolute/path/processing.json
```

`-check-config` проверяет форму и обязательные значения. Полный запуск отдельно открывает собственные файлы, ключи и подключения. Пример — [processing.example.json](processing.example.json), адреса и идентификатор в нём служат образцом.

Перед запуском требуется установленная принятая схема собственной PostgreSQL 18.7. Конфигурация не применяет миграции. Роль HTTP должна быть участником только `hp_processing_app`, роль отправщика — только `hp_processing_worker`, без bypass RLS, admin или purge. Оба DSN читаются из приватных файлов, ведут в одну базу и один узел, для обычного режима требуют проверки TLS имени базы. Пул имеет суммарно 2–10 соединений и делится между ролями. Ключ курсора — 32 байта. Каталог содержимого — собственный каталог с правами 0700, ключи и файлы DSN доступны только владельцу.

Порты 8443, 9443, 9444 привязываются к указанным приватным IP. Для сервера и исходящего клиента требуются разные действующие сертификаты, доверенные CA и точные SAN участников. Используются TLS 1.3 и mTLS. HTTP-проверка OPS показывает состояние процесса, допуска и базы. Игнорирование TLS проверок, прокси и перенаправления для внутренних запросов не поддерживаются.

Для воспроизведения проверки запустить из этого же каталога

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/postgres/verify_runtime.py \
  --go /absolute/path/to/go1.27.2/bin/go \
  --output /absolute/path/to/new-evidence-directory
```

Это отдельный процесс из собранного Linux-бинарника в локальном Docker с сетью `none`. Сценарий создаёт PostgreSQL 18.7 из закреплённого образа, временные TLS 1.3 сертификаты и локальных управляемых соседей. Тестовые DSN, токен, CSRF и ключи создаются во временном приватном каталоге, затем уничтожаются со стендом. В протокол включаются только обезличенные конфигурационные значения, версии, команды, хеши и выходы. В этом стенде используется явный флаг `-stand-config /absolute/path/stand.json`, который требует loopback для всех listeners и HTTPS-соседей, собственную локальную БД и режим TEST. Формирование stand-файла есть в `runtime_process_test.go`.

Обычный запуск остаётся CLOSED, пока нет согласованных авторитетных источников текущего состава воркеров, подтверждения CSRF/привязок и поколения удержанной очереди. IAM OpenAPI предоставляет регистрацию, запрос полномочий и барьер. Сессия с CSRF предоставляется через `getSession` только BFF. Регистрация, временные данные стенда и ограниченная проверка корректности собственного компонента не являются развёртыванием или подтверждением распределённого fencing.

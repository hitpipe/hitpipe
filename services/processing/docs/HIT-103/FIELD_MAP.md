# HIT-103. Состояния, поля и владельцы

Используются существующие маршруты, типы из утверждённого OpenAPI и таблицы Processing. Схемы трёх маршрутов совпадают в базовом и уточнённом OAS. Уточнение HIT-102 описывает происхождение `Operation.accepted_config_digest` и сохраняется в новых ответах.

| Вход и состояние | Проверка | Сохранённый результат |
|---|---|---|
| `PAUSE` из ACTIVE | BFF TLS 1.3 с проверкой сертификата, текущая сессия OWNER, область/эпоха, CSRF, идентификатор команды и ожидаемая ревизия. | Под блокировкой той же строки, что использует admission, атомарно записываются DRAINING, новая revision, `pause_accepted_at`, `drain_deadline_at = pause_accepted_at + 300 секунд`, метаданные команды и ссылка на полный ответ. HTTP 202 возвращает DRAINING. |
| Фоновое завершение DRAINING | Та же строка операции, уже допущенные дела этой операции, сохранённые сроки операции и эпизодов. | Сохранённый терминальный или явный незавершённый исход закрывает предшествующий эпизод. Для истёкшей незавершённой работы записывается `PAUSE_DRAIN_UNFINISHED`, ATTENTION либо UNKNOWN при возможном эффекте. Состояние PAUSED публикуется с новой ревизией после закрытия окна работы. |
| `PREPARE_RESUME` из PAUSED | Актуальные привязки проверяются у владельцев. Владелец очереди подтверждает область, поколение, полноту и срок. | Снимок с новой revision и точным содержимым в собственном файле. Команда возвращает Operation 202 в PAUSED. `getResumeSnapshot` отдаёт сохранённый снимок текущей ревизии. |
| `ACCEPT_RESUME` из PAUSED | Свежие полномочия, привязки, точный снимок и поколение, повторная проверка под ограниченной резервацией владельца, SQL CAS и SINGLE. | ACTIVE на новой ревизии и сохранённое решение для точного поколения. Удержанные сообщения передаются либо отбрасываются владельцем очереди после чтения подтверждённой записи. |
| Повтор команды | Тот же workspace, операция, актор, `request_id`, JCS SHA-256 и записанная ревизия. | Точный прежний Operation. Другой ввод с тем же ID конфликтует. Неопределённый COMMIT возвращает 503, проверка результата доступна после переподключения. |

| Поля | Источник |
|---|---|
| `Operations.items` | Ограниченный результат по одному workspace из собственной PostgreSQL с RLS. |
| `operation_id, revision, state, first_activation_at, accepted_config_id, drain_deadline_at` | `hp_processing.operations`. Изначальная граница активации и выбранная конфигурация при паузе и возобновлении остаются прежними. |
| `accepted_config_digest` | Принятая запись `accepted_configs.digest`; сверка RFC 8785 JCS с фактическим `canonical_config`. |
| `name` | Сохранённое представление исходной активации в файлах владельца с проверкой ссылки, результата и метаданных команды. Для операции до активации используется сохранённый черновик. |
| `connection_health` | При чтении SQL — UNCHECKED. READY в сохранённом ответе PREPARE/ACCEPT соответствует проверке владения и привязок при принятии команды. |
| `LifecycleCommand` | `command.request_id` обязан совпадать с X-Request-ID, `expected_revision` обязательна и совпадает с If-Match при его наличии; `action`, `resume_snapshot_id`, `held_disposition` и `reason` проверяются по OAS и действию. Свободная причина хранится только в expiring файле. |
| `snapshot_id, operation_id, revision, created_at` | UUID Processing, та же операция и ревизия результата PREPARE, время владельца. |
| `signal_count, serialized_bytes, oldest_received_at, gaps` | Полная проверенная сводка от владельца очереди; у достоверно пустой очереди 0, 0 и null. Отсутствующее подтверждение даёт ошибку. |
| `expires_at` | Верхняя граница от владельца очереди, ограниченная сроком первого удержанного сигнала и сроком связанного содержимого Processing. Повтор не продлевает срок. |
| Полный ответ, снимок и факт решения очереди | Связанные контрольными суммами файлы владельца под существующей ссылкой `drafts.prose_ref/prose_sha256`. SQL `user_commands` хранит только идентификаторы, digest, ревизии и факт принятия. Файлы подтверждаются до публикации SQL-ссылки. |
| История незавершённого дренирования | `safety_history` и `history_content` через существующий writer HIT-79; читается строгой проекцией HIT-95. |

`PROCESS_ELIGIBLE` направляет точное поколение владельцу очереди для прежнего admission с `Session.created` относительно исходной границы. `DISCARD_WITH_GAP` сохраняет окно, счётчик, размер, возраст и уже известные gaps для точного поколения и разрешает владельцу отбросить его без передачи сигналов. Решение `CommittedResume` читается только после подтверждённой строки SQL и сверки журнала. Резервация снимка сама не изменяет очередь. В случае неоднозначного COMMIT владелец читает сохранённое решение и применяет его по идентификатору один раз.

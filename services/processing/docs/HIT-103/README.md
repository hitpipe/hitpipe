# HIT-103. Пауза и безопасное возобновление операции

Codex по делегации Тимофея Патрушева / Tim1hik. Контракт HIT-103, редакция 1, восемь критериев. [Jira](https://hitpipe.atlassian.net/browse/HIT-103) · [PR №71](https://github.com/hitpipe/hitpipe/pull/71).

Существующий приватный HTTPS/mTLS сервер Processing принимает PAUSE, PREPARE_RESUME, ACCEPT_RESUME и читает операции и снимки. Пауза и новый допуск сериализуются по одной строке операции. Команда 202 сохраняет DRAINING, завершение отражается после фоновой обработки. Уже допущенное дело сохраняет identity и своё знание об эффекте. Возобновление требует текущего снимка от владельца очереди и повторной проверки привязок, возвращает ту же операцию с исходной границей активации и принятым хешем. [Карта полей и состояний](FIELD_MAP.md).

Ветка PR основана на коде HIT-102 `52779ea`. Зависимость в Jira завершена, независимое ревью подтвердило 12/12, PR №63 остаётся открытым. Наблюдаемый main `ce771d3`. Совместимость проверена в отдельной ветке HIT-103 с открытыми предшественниками HIT-95/98/99/104 и прежним интеграционным стеком HIT-102. [Сверка источников](source-audit.json).

|---|---|
| 1. База, повторное использование и карта данных | Зафиксированы база PR, раздельный интеграционный коммит и SHA исходников. Переиспользованы активация, OAS-валидация, роль приложения, SQL-блокировка admission, ворота фактического старта и файлы владельца. |
| 2. HTTPS/mTLS, CSRF, параметры и полномочия | Настоящие TLS 1.3 и сертификаты; неверный или отсутствующий сертификат, сессия/CSRF, метаданные команды, ревизия, чужая операция, запрещённые authority-заголовки, неизвестные поля, дубли и null проверены в `TestLifecycleWrongSnapshotBindingAndAuthority`. |
| 3. Атомарная пауза и срок | `TestLifecyclePauseSerializesWithAdmission` и полный цикл проверяют блокировку совместно с admission, точную границу 300 сек, удержание DRAINING до срока и запись UNKNOWN при возможном эффекте. |
| 4. Фактический readback и восстановление | Приём PAUSE показывает DRAINING, отдельный прогон воркера переводит в PAUSED. Повтор после переоткрытия listener и файлов сохраняет прежний ответ и сроки. Прежние проверки RLS и SINGLE пройдены. |
| 5. Проверяемый снимок | Фактические count/bytes/oldest вычислены из удержанных входов контролируемого владельца; подтверждённая пустая очередь даёт 0/0/null. Проверены неполнота, неизвестная/чужая операция, другое поколение, срок и изменённый ID. |
| 6. Выбор судьбы удержанных сигналов | Владелец стенда применяет подтверждённое решение один раз. Для PROCESS_ELIGIBLE допустимый сигнал проходит admission, старая Session отклоняется. DISCARD_WITH_GAP не передаёт сигналы и сохраняет фактический объём пропуска. Изменившаяся привязка и недоступный владелец блокируют возобновление. |
| 7. Ревизия, повторы и ошибки | Конкурентные PAUSE фиксируют одну команду, другой digest конфликтует. Проверены точный ответ после потери COMMIT ACK, сбой fsync с откатом, неизменные case/config/owner/lineage и `ever_dispatch_fenced`. |
| 8. Настоящий стенд и регрессии | Работа через существующие HTTP-маршруты, PostgreSQL 18.7 и fsync owner files. Go 1.27.2: race, vet, build. В интеграции — HTTP Intake 409 на паузе, история HIT-95 200 с явным исходом, HTTP Intake 202 после разрешённого возобновления. |

Сроки проверены управляемыми часами в основном сценарии. Совместимость с фактическим SQL-временем чтения истории проверена на заранее допущенном эпизоде, чей срок уже наступил. Запуски `race`, `vet` и сборка сделаны на хосте Darwin. База запускается отдельно в Linux, тестовый бинарник собран с CGO=0. Неуспешные промежуточные прогоны и причины находятся в архиве разработки.

На стенде управляются очередь, внешние привязки, сессия, полномочия, roster фонового воркера и ворота старта. Очередь хранится и применяется её владельцем. При настоящей композиции владелец должен гарантировать полноту снимка, удержание конкретного поколения при записи и однократное применение подтверждённого решения. Сроки работы недоступного сервиса и запись в реальные Stripe/ClickUp этим стендом не квалифицированы.

Имя, исходное доказательство привязки и полные ответы доступны в пределах срока существующего содержимого HIT-102. Если этот источник утрачен или истёк, операции, которым требуется его проверка, закрываются с ошибкой. Бессрочный жизненный цикл после удаления этих материалов потребует утверждённого источника долгоживущих метаданных. Передача результата и независимая проверка учитываются отдельно в Jira.

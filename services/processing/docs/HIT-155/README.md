# HIT-155. Контейнер и восстановление Processing на одной сборке

Codex по делегации Тимофея Патрушева (Tim1hik). [HIT-155](https://hitpipe.atlassian.net/browse/HIT-155) · [Draft PR №88](https://github.com/hitpipe/hitpipe/pull/88)

Из интеграционного исходника `1ed91653a747b47a98f2738ca0d831a38cebc98a` собран образ Linux arm64 с манифестом `sha256:91a2b1b19d0d22fe783b74c3ecf338dd0f3e20a2863a3b3cdb061d4b69312e51`. Один загруженный образ использовался для двух стартов проверки HIT-145 и шести стартов сценария HIT-128. Независимая повторная сборка в чистой копии на том же Docker Engine воспроизвела манифест, конфигурацию, слой и бинарник.

В интеграции проявился ожидаемый переход `WAITING_DATA/READER_UNAVAILABLE` при ответе управляемого Intake. Старый тест делал исходный снимок истории до этой записи. Тест теперь дожидается её и по-прежнему сравнивает всю историю и точные байты квитанции. [Журнал ранних попыток](verification/first-attempts.md).

Проверка выполнена на одном локальном Docker Engine с синтетическими данными и управляемыми mTLS-соседями. Продуктовые API, DDL, бизнес-правила и сроки сохранены. Внешние Stripe/ClickUp, рабочий rollout, адресное удаление и эксплуатационное восстановление не входили в прогон.

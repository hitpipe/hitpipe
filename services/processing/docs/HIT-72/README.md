# HIT-72 — результат реализации

Выполнено Codex по поручению Тимофея Патрушева / Tim1hik.

Проверен main dd726339b5b9f5e62cb2150d801a40d05c319294: весь Processing
(domain, application, adapters, CLI, tests). В нём есть financial kernel,
EvaluatePaidOrder и файловый fixture-reader; канонического SourceFacts projection
нет. Это проверка существующего исходника, не повтор закрытой HIT-60.
Предыдущие результаты HIT-60 использованы как исторический контекст.

Добавлен независимый преобразователь принятого SourceFacts. Данные проходят
проверку структуры по сгенерированным из закреплённой OAS правилам. Проверяются
все обязательные поля, типы/null, enum, форматы и числовые границы, точные имена,
дубликаты, дополнительный JSON и ожидаемая identity. Policy остаётся локальной;
facts_id/digest и точные исходные строки времени сохранены отдельно.

Существующие eligibility.Evaluate и EvaluatePaidOrder переиспользованы без правок.
Тестовая композиция подтверждает VALID, INELIGIBLE/REFUND, INCOMPLETE и
REFRESH_REQUIRED на точной границе. Отсутствующее обязательное поле — невалидное
сообщение и явная ошибка адаптера; допустимый nullable unknown — неизвестный факт.
Ошибка/отмена источника не вызывают повтор. VALID не разрешает внешнее действие.

Проверенная кодовая версия: fa7d49d (полный SHA в verification/commands.json).
Среда: Go 1.27.2, darwin/arm64, GOTOOLCHAIN=local. Реальные команды и UTC-время,
exit codes, stdout/stderr и SHA-256 находятся в verification/. 6 пакетов PASS,
289 завершившихся PASS событий тестов/подтестов, из них 87 в новом пакете.
Это не число независимых финансовых сценариев. go vet, регенерация и diff — exit 0.
source-audit.json фиксирует файлы, неизменность kernel/consumer/go.mod и инспекцию
отсутствия сетевых/дисковых/DB вызовов, wall clock, retry и dispatch в адаптере.

Новые проверки выполнены локально на macOS. Запуски CI отражаются отдельно в PR;
их статус нельзя выводить из локальных результатов. CI использует существующие
workflow репозитория; новый учебный цикл, отчёты или настройки CI здесь не создаются.

Ограничения: нет sender authentication, проверки digest, полномочий, epochs/start
и server wiring. Действующие Intake/провайдеры и сквозная интеграция не проверены.
Только синтетические сообщения. Изменения не являются самостоятельной приёмкой
MVP, независимым ревью или разрешением запуска.

Машинное представление результата по штатному маршруту задачи с корнем репозитория:
`.project-os/results/HIT-72.json`. Отдельный коммит доказательств позволяет закрепить
реальный SHA кода без цикла самоссылки на SHA результата.

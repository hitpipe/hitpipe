# HIT-148. Адресное удаление содержимого дела

Codex по делегации Тимофея Патрушева (Tim1hik). [HIT-148](https://hitpipe.atlassian.net/browse/HIT-148) · [Draft PR №86](https://github.com/hitpipe/hitpipe/pull/86) · [Принятая поправка](https://github.com/hitpipe/project-os/blob/0dc25affc7cb19b1a74a16d80b93eac0d9961c05/contracts/hitpipe/case-deletion-2026-11-22/CASE_DELETION_AUTHORITY_RU.md).

Четыре критерия выполнены в контролируемом TEST на PostgreSQL 18.7. Проверенный Processing `107ed4e3ae0d43300a09dea10b2d43ad4423efc1`, принятый издатель IAM HIT-154 `c715a079ab57d4c9e7b56862f7f2584c792b74b0`.

| Критерий | Фактическое наблюдение |
| --- | --- |
| Ограниченный допуск | Два синтетических пространства. Действующий владелец подтвердил точные версии. Чужая область, версия другого дела, чужой владелец, подмена подтверждения, неизвестное поколение или отсутствие действующей записи отклонены. App и worker не смогли применить подтверждённое удаление. |
| Точный физический эффект | Два файла выбранного дела физически удалены. Третья выбранная версия исключена из чтения дела, её общий живой файл сохранился. Байты другого дела и соседнего пространства совпали с копией до удаления. Чтение истории сохранило исходный ID, статус и `expires_at`, чтение дела вернуло HTTP 200 без выбранного контекста. |
| Устойчивость | Необъяснимо пропавший файл не дал квитанции и не затронул другие выбранные версии. Сбой транспорта после применения оставил IAM в APPLYING, повтор переиспользовал доказательство. IAM проверил конкретный журнал, SQL и результат на файловом слое, прежде чем записать APPLIED. Повтор APPLIED не отправил новую квитанцию. |
| Безопасный restore | Восстановлены старые SQL и файловая копия по штатной схеме HIT-128. Processing остался CLOSED и вернул 503 при старой ревизии и недоступном издателе. После повторного удаления и проверенной квитанции поколения 2 настоящий `WithCurrent` разрешил открыть существующий start gate. Ни одного вызова Delivery после восстановления. Контрольные суммы SQL сравнили исходник, копию и восстановление. |

SQL минимальной истории, идентификаторов, состояния внешней записи и защиты от повторного эффекта остаётся источником метаданных. Тела не входят в журнал применения или квитанцию. Квитанция привязана к точному списку версий, поколению, ревизии APPLYING и фактическому устойчивому результату. На отдельном TEST-слушателе проверен настоящий издатель. Обычная регистрация Processing использует управляемый mTLS-стенд, текущий OWNER проверяется в IAM PostgreSQL. Этот стенд не участвует в выдаче решения, проверке квитанции или блокировке WithCurrent.

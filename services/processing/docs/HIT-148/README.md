# HIT-148. Адресное удаление содержимого дела

Codex по делегации Тимофея Патрушева (Tim1hik). [Задача](https://hitpipe.atlassian.net/browse/HIT-148) · [Draft PR №86](https://github.com/hitpipe/hitpipe/pull/86).

**Подписанный инвентарь подключён и проверен. Адресное удаление и повторное применение перед открытием остаются заблокированы.**

Processing `0eba954c24652655cfc661fc63628b2097ebd33e` прочитал решённый владельцем `APPLYING` и полный пустой снимок соседнего workspace через настоящий mTLS и отдельный издатель `c715a079ab57d4c9e7b56862f7f2584c792b74b0`. Чужая область, поколение, клиентский сертификат, серверный пин, ключ подписи и недоступный источник были отвергнуты. Проверка только читает текущий снимок, из неё не следует готовность Serving. Go race, vet, сборки и регрессии Processing на PostgreSQL 18.7 прошли.

Для включения адресного режима нужна интеграция двух вызовов подтверждения с Processing: проверяемое свидетельство устойчивого применения для `ApplicationAuthority.WithApplied` и синхронный переход восстановленного Processing под локальным барьером издателя `WithCurrent`. Реализации в закреплённом испытательном контуре HIT-154 работают с собственной синтетической копией. Сырые журналы и Git-проверка это различают.

| DoD | Текущее состояние |
| --- | --- |
| Авторитетный допуск и границы роли | Проверены получение подписанного решения и отказы по области, поколению и доверию. Подтверждённое удаление под существующей ролью пока не квалифицировано. |
| Точное удаление и сохранение safety, общих ссылок и fence | Адресный режим закрыт, пройдены регрессии прежней очистки. |
| Прерывание, повтор и чтение результата | Синтетический прогон HIT-154 и регрессии HIT-128 пройдены. Фактического повторного адресного применения Processing пока нет. |
| Повтор реестра до открытия после restore | Подписанный снимок доступен. Не хватает доверенной композиции проверки квитанции и общего барьера открытия. |

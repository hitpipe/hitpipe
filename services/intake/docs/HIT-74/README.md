# HIT-74 — изолированное файловое хранение Intake

Адаптер `internal/adapters/contentstore` сохраняет только ограниченное содержимое
(1…65536байт), не сырой webhook и не секреты. SQL, сервер и Stripe не подключены.

Исходная база: main ce771d37505e7770003d0796ae932556d06b7bab, подтверждена прямым
чтением GitHub main. В полном локальном дереве services/intake отсутствовал;
поиск GitHub по HIT-74 и package contentstore не нашёл готового решения.
PR73 не считается слитым и не нужен изолированному адаптеру; чужие PR не менялись.
Новая рабочая копия codex/HIT-74-content сохраняет незакоммиченные отчёты пользователя.

Порядок Put: CSPRNG UUIDv4 без содержимого в имени → exclusive temporary file0600 →
write → file.Sync → close → atomic rename → directory.Sync → Ref.
Каталог заранее выделяется владельцем с0700. Open требует канонический путь без
символических ссылок во всех компонентах и проверяет identity открытого каталога.
os.Root удерживает дескриптор, имена разрешены только UUIDv4. Read использует
O_NOFOLLOW/NONBLOCK, проверяет regular file,0600, размер и SHA256. Нет payload,
путей или исходных сообщений ОС в ошибках. На любом отказе Put не возвращает Ref;
после rename возможен полный orphan, который не выдаётся за отсутствие записи.

Часы передаются явно. Ref и его срок — доверенный вход владельца, а не данные
клиента. Адаптер ограничивает общий срок90суток (Intake source facts); для удержанных
сигналов владелец обязан передавать не более72часов от первого приёма, не продлевая
срок на повторе. Read отказывает на точной границе expiry и повторно после чтения.
Нет собственной параллельной базы ссылок или автоматического назначения сроков.

Purge принимает полный согласованный снимок referenced IDs; nil означает неизвестный
снимок и отвергается. Удаляет только UUID-файлы и собственные .tmp-UUID, которых нет
в снимке, синхронизирует каталог. Неизвестные имена не удаляет, ссылки/каталоги не
обходит. Эксклюзивное владение корнем и отсутствие конкурентных внешних publishers
обязательны. Mutex защищает только этот экземпляр, не SQL или другие процессы.

Проверки используют отдельные t.TempDir с синтетическими bytes. Проверены права,
случайные имена, предельный размер, traversal, symlink root/leaf, digest/tamper,
expiry, неизвестный reference snapshot и сохранение referenced файла. Для каждого
этапа write/file_sync/rename/directory_sync проверены injected error и реальное
завершение дочернего процесса os.Exit(23) до операции; фактически оставшиеся файлы
прочитаны и очищены. Это контролируемая остановка процесса, не power-loss тест.
Закрытый root даёт настоящую ошибку ОС без успешного результата.

Первые тесты выявили, что macOS t.TempDir использует /var, являющийся системной
ссылкой на /private/var. Тестовый setup теперь явно получает канонический путь;
запрет symlink в самом адаптере не ослаблен.

Воспроизведение: Go1.27.2, `cd services/intake; go test -race -count=1 -json ./...;
go vet ./...; go build ./...`. Протоколы и точный SHA — ../../evidence/HIT-74.
Других принятых Intake-модулей в исходном main нет; закрытые учебные gates не запускались.

Ограничения: локальный fsync и остановка процесса не подтверждают свойства рабочего
диска, надёжность питания/flush, фиксацию SQL ref, webhook ACK или восстановление
развёрнутой системы. Принятие Ref вызывающим кодом и atomic SQL linkage — другая
задача. Независимое ревью и человеческая приёмка не выполнены.

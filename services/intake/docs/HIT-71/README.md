# HIT-71 — миграция Intake и сохранённые проверки

Обновление по прямому указанию пользователя «замени версию»: тестовый стенд
переведён на PostgreSQL **18.7 Alpine**, immutable index digest
`sha256:75dcac3dfb1cd01ca3536910bbc84128759362f8b118bf8c55b38a94f68f3b73`.
На коде `1b9ea201f7ec64cd240f08e887ab643c5a112f38` повторно прошли все 377
SQL-проверок, exit 0; сервер сообщил ровно 18.7. Протоколы и команды сохранены
отдельно в `verification-18.7/`, исходный прогон на 18.6 остаётся в `verification/`.
Миграция SQL не менялась. Сведения о registry manifest — `postgres-18.7.json`.
Специальное воспроизведение CVE не выполнялось; это повтор существующих тестов.

## Текущее согласование версии

PostgreSQL **18.7 Alpine** и указанный выше точный digest согласованы поправкой
[HP-CCR-POSTGRES-20261114](https://github.com/hitpipe/project-os/blob/d9eb399d9cc0528f1beae6153851ab5020741ea5/contracts/hitpipe/security-2026-11-14/POSTGRES_SECURITY_PATCH_RU.md).
Она заменяет только прежнюю версию PostgreSQL 18.6 и закрепление образа;
SQL, API, роли, RLS и параметры надёжного сохранения не меняются.
Предыдущий запрос на решение руководителя о допустимой версии больше не является
текущей инструкцией: он сохранён ниже как история первоначального состояния 18.6.

Применение поправки к действующей редакции договора HIT-71 и снятие её прежней
серверной паузы фиксируются в Project OS отдельно. Этот README сам по себе
не снимает паузу, не регистрирует новый результат, не выставляет READY/PASS и
не заменяет независимого проверяющего. Исполнитель продолжает с существующего PR,
сохраняет проверенную редакцию `1b9ea201f7ec64cd240f08e887ab643c5a112f38`, её
377 проверок и прежние доказательства. После применения поправки он обновляет
ссылки результата на действующий договор и выполняет обычную проверку готовности.
Существующее ограничение по специальному воспроизведению CVE остаётся явным.

## История первоначального прогона на 18.6

Далее сохранён отчёт о причине остановки **до обновления и согласования 18.7**.
Эти сведения описывают прошлое состояние, а не новый запрет использовать 18.7.

Исторический статус на этапе 18.6: **работа удержана, к независимому ревью не готова**.

После личного согласия «план подтверждаю» проверен текущий main
`ce771d37505e7770003d0796ae932556d06b7bab`. Поиск охватил всё tracked-дерево,
SQL, названия миграций и services/intake. В main нет services/intake;
найден только исторический snapshot `docs/labs/pr12/upstream/architecture/formal/sql/intake.sql`,
который не является owner-миграцией принятой MVP-схемы. Исторический результат
HIT-58 (11303) прочитан; его UNKNOWN не отменяют принятую позже схему.
PR #32 повторно проверен: открыт, не слит, head
`e64f4ff4310c597414f768ea705b6ceb1221e1b2`. Код из PR не переносился.
Чужие локальные изменения сохранены в исходной рабочей папке; работа выполнена
в отдельном worktree от main.

Создана точная миграция HP-MVP-SQL-INTAKE и одноразовый тестовый стенд.
Проверены hashes GitHub-источников полного архитектурного реестра и всех
закреплённых файлов stack inventory. Ссылки и результаты сверки — в source-audit.json.

Официальный bootstrap 11896 собран из 7 частей; авторы/updateAuthor,

Протокол v2 закреплён на `685e797bf32f71fd4ca42cd5f594b80912736473`.

На коде `e809cc7713e827a7bb82efeb384f65e15624c7a5` выполнены **377 ограниченных
SQL-проверок**, exit 0. Это число проверок, включая элементы матрицы прав,
а не число независимых сценариев безопасности. PostgreSQL 18.6 Alpine на точном
закреплённом digest, Linux/arm64 в Docker; Python 3.12.6, host macOS arm64.
Команды, время, SHA, длительность, stdout/stderr и hashes — в verification/.
Проверены таблицы, функции, триггеры, индексы, матрица прав и реальные подключения
ролей, RLS, immutable receipt, TTL, count/byte quotas и две конкурентные гонки.
В main нет существующих тестов Intake; исторические Go/учебные gates не запускались.
Другие сервисы не менялись. Проверка git diff --check завершилась с exit 0.

При обязательной проверке актуальных security advisories обнаружено:

- [CVE-2026-120154](https://www.postgresql.org/support/security/CVE-2026-120154/)
  опубликована 12 ноября 2026; затрагивает PostgreSQL до 18.7.
  При определённых ON CONFLICT запросах пользователь с SELECT/INSERT/UPDATE
  может прочитать строки вопреки RLS. Такие SQL-права предусмотрены схемой
  у app/worker. Это существенная применимость advisory; воспроизведение
  конкретной атаки на этой схеме не выполнено.
- [Релиз 18.7](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)
  содержит исправления безопасности. На первоначальном этапе 18.6 этот
  черновик ещё не менял закрепление на 18.7.
- HP-MVP-A-008 требует проверить advisories до применения cohort и запрещает
  скрыто менять уязвимый pin; BOUNDARIES HIT-71 требует остановки при существенном
  конфликте и CCR при изменении закреплённого договора.

На первоначальном этапе требовалось решение руководителя: штатно разрешить
конфликт закреплённой версии через CCR, указав точную допустимую версию и OCI digest.
Запрос относился к состоянию 18.6; действующая поправка версии приведена выше.
Обычное подтверждение исполнителя не заменяет это решение. In Review/Done,
самостоятельный PASS, FORCE или изменение архитектурного источника не выполнялись.

Изоляция строк через тестовый hp.workspace_id не является проверкой полномочий
пользователя. Положительные тесты не покрывают новую CVE и не подтверждают
безопасность PostgreSQL 18.6. Не проверены подпись webhook, надёжность файлового
сохранения, HTTP ACK, провайдеры, рабочее развёртывание или сквозная интеграция.
Рабочие базы, окружения, внешние credentials и закрытые задачи не затронуты.

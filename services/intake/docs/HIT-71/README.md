# HIT-71 — сохранённый черновик и препятствие

Обновление по прямому указанию пользователя «замени версию»: тестовый стенд
переведён на PostgreSQL **18.7 Alpine**, immutable index digest
`sha256:75dcac3dfb1cd01ca3536910bbc84128759362f8b118bf8c55b38a94f68f3b73`.
На коде `1b9ea201f7ec64cd240f08e887ab643c5a112f38` повторно прошли все 377
SQL-проверок, exit 0; сервер сообщил ровно 18.7. Протоколы и команды сохранены
отдельно в `verification-18.7/`, исходный прогон на 18.6 остаётся в `verification/`.
Миграция SQL не менялась. Сведения о registry manifest — `postgres-18.7.json`.
Специальное воспроизведение CVE не выполнялось; это повтор существующих тестов.

Изменение относится к коду тестового стенда. Согласованное изменение baseline
и frozen договора Project OS через CCR пока не подтверждено; прежняя серверная
пауза не снята, готовность к независимому ревью не заявлена.

Ниже сохранён отчёт о первоначальном прогоне и причине остановки **до обновления**.

Статус: **работа удержана, к независимому ревью не готова**.

При обязательной проверке актуальных security advisories обнаружено:

- [CVE-2026-120154](https://www.postgresql.org/support/security/CVE-2026-120154/)
  опубликована 12 ноября 2026; затрагивает PostgreSQL до 18.7.
  При определённых ON CONFLICT запросах пользователь с SELECT/INSERT/UPDATE
  может прочитать строки вопреки RLS. Такие SQL-права предусмотрены схемой
  у app/worker. Это существенная применимость advisory; воспроизведение
  конкретной атаки на этой схеме не выполнено.
- [Релиз 18.7](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)
  содержит исправления безопасности. Этот черновик не меняет pin на 18.7.
- HP-MVP-A-008 требует проверить advisories до применения cohort и запрещает
  скрыто менять уязвимый pin; BOUNDARIES HIT-71 требует остановки при существенном
  конфликте и CCR при изменении закреплённого договора.

Необходимо одно решение руководителя: штатно разрешить конфликт закреплённой
версии через CCR/обновление baseline, указав точную допустимую версию и OCI digest.
После этого можно согласовать изменившийся план и выполнить повторные проверки.
Обычное подтверждение исполнителя не заменяет это решение. In Review/Done,
самостоятельный PASS, FORCE или изменение архитектурного источника не выполнялись.

Изоляция строк через тестовый hp.workspace_id не является проверкой полномочий
пользователя. Положительные тесты не покрывают новую CVE и не подтверждают
безопасность PostgreSQL 18.6. Не проверены подпись webhook, надёжность файлового
сохранения, HTTP ACK, провайдеры, рабочее развёртывание или сквозная интеграция.
Рабочие базы, окружения, внешние credentials и закрытые задачи не затронуты.

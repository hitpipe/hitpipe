# HIT-119. Единый процесс Intake

Собран `cmd/intake`. Он использует принятые webhook HIT-107, SourceFacts HIT-117
и отправщик HIT-118, включая принятое улучшение HMAC. База ветки — опубликованный
HIT-118. Ветви зависимостей открыты и не слиты в main. Сохранены исходная SQL-схема,
wire-контракты и поведение durable receive, файлового хранения и outbox.

Один TLS 1.3 listener обслуживает подписанный `POST /webhooks/stripe/{endpoint_id}`
и `POST /internal/v1/source-facts/read`. Для второго маршрута необходим
проверенный сертификат Processing с ожидаемым SAN. Другой сертификат и отсутствие
сертификата получают отказ. Служебных маршрутов нет. Стандартный business-порт
контракта — 8443, тест выполняется на отдельном loopback-порту.

Webhook, чтение фактов и sender имеют общий процесс, контекст отмены и один
шлюз допуска. Запись сигналов и фактов используют общий пул роли app. Sender
использует отдельную роль worker и тот же workspace-каталог. Мигратор используется
внешней подготовкой тестовой базы. Runtime никогда не запускает миграции.
Цикл sender обрабатывает ограниченную порцию, ждёт между опросами и сохраняет
существующие lease, backoff и Retry-After. Сетевое ожидание не держит SQL-транзакцию.

## Запуск

Для полного воспроизведения установите Go 1.27.2 и запустите Docker. Из корня
репозитория выполните:

```sh
python3 services/intake/tools/check_receipt.py --go /path/to/go1.27.2 --output /tmp/hit119-verification
```

Команда поднимает отдельный PostgreSQL 18.7 (закреплённый образ), готовит
изолированные тестовые базы и сертификаты, собирает самостоятельный бинарник
через `go build` и дважды запускает его дочерним процессом. Стенд и временный
бинарник удаляются по окончании. Для запуска отдельно с уже подготовленными
локальными зависимостями:

```sh
cd services/intake
go build -o /tmp/intake ./cmd/intake
/tmp/intake -config /path/to/lab/sandbox.json
```

Пример `sandbox.json` с выделенными портами:

```json
{
  "profile": "sandbox",
  "listen": "127.0.0.1:8443",
  "database_port": 55432,
  "stripe_origin": "https://127.0.0.1:18443",
  "processing_address": "127.0.0.1:28443",
  "batch": 1,
  "poll_ms": 100
}
```

В каталоге 0700 рядом с конфигурацией нужны `content/` (0700),
`intake-server.pem/key`, `intake-client.pem/key`, `service-ca.pem`, `stripe-ca.pem`,
`webhook.secret` и `stripe.secret`. Закрытые ключи и файлы секретов должны иметь
права 0600. Конфигурация и argv содержат только пути и параметры. База
`intake_test` готовится принятым `tests/postgres/bootstrap.sql` и исходной
миграцией под `hp_intake_migrator`; тестовая установка соответствует seed в
`tests/process/intake_test.go`. Используйте только синтетические ключи и данные.
Обычный режим или отсутствие конфигурации завершаются закрытым отказом и не
запускают listener. Ошибочные, дублирующиеся и конфликтующие поля отвергаются.

## Что наблюдалось

Подписанный webhook вернул пустой 204, чужой сертификат и отсутствие сертификата
получили 401 на SourceFacts, а сертификат Processing дал 200 с полными фактами.
Пока тестовый Processing задерживал ответ, Intake повторно принял подписанный
webhook без дублирования и прочёл факты. SQL и файл подтвердили исходные байты.
Первый SIGTERM завершил процесс с кодом 0, пока запись находилась в CLAIMED и
Processing уже зафиксировал приём. После нового запуска на тех же данных истёкшая
аренда была восстановлена. Повтор послал тот же message_id и байты и получил
DUPLICATE, после чего outbox стал ACKED. Остались один сигнал, один факт, одна
строка outbox и одна квитанция Processing. Второй SIGTERM также завершился с кодом 0.

Чистый проверенный код `b4c4387d13cdcd41ca08cf64d80192d4d1e58b69`. Восемь команд с кодом 0.
145 успешных тестовых событий в unit и 290 в полном интеграционном
прогоне с учётом unit. 377 SQL-проверок, без отказов и пропусков.
[Короткий протокол](test-transcript.txt) · [Команды](commands.json) ·
[Полный журнал](integration.stdout) · [Источники](source-audit.json)

- Обычный запуск закрыт до появления настоящих портов установки, полномочий и допуска. Тестовый профиль допускает только 127.0.0.1 и собственную тестовую базу.
- Тестовые Stripe, Processing и полномочия управляемые. Промышленная установка, IAM/control, хранение рабочих секретов, deployment и финансовая обработка не проверялись.
- Проверен перезапуск на сохранённых PostgreSQL и каталоге содержимого. Потеря всего хранилища, продакшен-диск, очистка по срокам и эксплуатационная квалификация вне задачи.
- До 8 HTTP-обработчиков, один цикл отправки и параметры таймеров относятся к стенду. Новых продуктовых порогов и маршрутов нет.

# HIT-107. Приём webhook Stripe

На HTTPS listener Intake добавлен `POST /webhooks/stripe/{endpoint_id}`.
Lookup по ID маршрута возвращает проверенную установку с рабочей областью,
подключением, аккаунтом, режимом и ревизией. Перед вызовом приёма отдельный порт
проверяет текущий допуск. Значения из заголовков и payload не выбирают владельца.
Оба порта обязательны. Секрет выдаётся штатному проверяющему HIT-73 по ID установки.

Обработчик ограничивает исходное тело 256 КиБ, заголовок подписи 2048 байт и время
чтения. HIT-73 проверяет HMAC v1 над исходным телом с допуском 300 секунд до разбора
JSON. Категории ошибок передаются в HTTP без исходных байтов или текста зависимостей.
Принятые OAS, DDL, алгоритмы подписи и нормализации не менялись.

В успешном тесте до завершения commit файл уже записан, а новые строки signals
и outbox ещё не видны другому SQL-подключению. HTTP-ответ не получен. После
завершения commit приходит пустой `204`, обе строки видны, файл читается по ссылке и
его контрольная сумма совпадает. SQL-транзакция завершена до отправки HTTP-ответа.
Повтор заново проверяет подпись и возвращает исходную запись с теми же временем
приёма и сроком хранения. Оба предела квоты дают `429` для нового события.

В тесте отказа изменённые байты с прежней подписью дают `401`; правильно подписанный
повреждённый JSON даёт `400`. После ошибочных запросов signals/outbox и каталог пусты.
Неопределённый commit даёт `503`. После потери HTTP-соединения вслед за commit
повтор через новый listener и экземпляр обработчика подтверждает тот же приём.

Проверенный код `20aa3946ac6f5e6a7d82469bbee5a95d3b4cd3d7`. Все шесть команд завершились с кодом 0:
132 успешных события unit-тестов, 189 в интеграционном прогоне (включая unit),
377 SQL-проверок, vet, сборка и проверка модулей. Пропусков и отказов в итоговом
прогоне нет. [Короткий протокол](test-transcript.txt), [команды и среда](commands.json),
[исходный журнал интеграции](integration.stdout), [реестр источников](source-audit.json).

Повторить с Go 1.27.2 и доступным Docker:
```sh
python3 services/intake/tools/check_receipt.py --go /path/to/go1.27.2 --output /tmp/hit107-verification
```
Команда создаёт и удаляет собственный PostgreSQL 18.7. Права RLS и схема штатные.

Ограничения:

- Настоящий Stripe, рабочие секреты/установка, IAM и runtime допуска не подключены. Порты установки и допуска в стенде управляемые.
- HTTPS проверен на loopback с проверяемым сертификатом. Edge, промышленное развёртывание, SQL TLS и восстановление после потери питания не проверялись.
- HTTP 204 подтверждает локальный приём. Сетевая доставка в Processing, sender, внешние действия и Stripe-to-ClickUp не входят в HIT-107.

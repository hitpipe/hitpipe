# HIT-118. Отправка сохранённого сигнала в Processing

Отправщик берёт только due-записи в явно переданной рабочей области и подключении.
В короткой транзакции роль Intake worker устанавливает локальный RLS scope и
захватывает одну строку. Каждая попытка получает новый токен аренды. Изменить
outbox может только текущий токен, пока аренда действует. Чтение файла и отправка
идут вне SQL-транзакции. Глобальный job_index не используется для поиска payload.

Перед чтением проверяются актуальная authority, epoch и источник. Перед реальным
TCP connect и записями в соединение, в том числе TLS, действует тот же обязательный
gate. Scope и аренда также перечитываются PostgreSQL. Неподтверждённая установка,
нарушенная целостность файла, истёкшее содержимое или изменившийся epoch не позволяют
начать отправку. Нет разрешающего рабочего порта по умолчанию.

HTTPS/mTLS передаёт именно сохранённые байты в POST /internal/v1/intake-signals.
Размер, границы схемы, RFC8785-представление, digest файла и digest сообщения
проверяются по имеющемуся SQL projection. TLS 1.3 проверяет CA и имя Processing,
сервер проверяет удостоверение Intake. Redirect и скрытые повторы транспорта
отключены. Повтор планируется с backoff и jitter, соблюдает Retry-After и исходное
истечение. Номер попытки не меняет message_id, message_digest и времена сигнала.

Квитанции APPLIED, DUPLICATE и HELD подтверждают приём. CONFLICT, неверный ID и
повреждённая квитанция удерживают запись. Состояние signals не меняется при
ACK. В тесте потери ответа Processing сначала реально фиксирует свой синтетический
inbox, затем закрывает HTTPS-соединение. Intake сохраняет PENDING и время повтора.
Новый экземпляр отправщика посылает те же байты, получает DUPLICATE и фиксирует ACKED.
Исходная строка, файл и срок сохраняются. Отдельный тест отменяет локальный
commit ACKED и показывает, как новая аренда восстанавливает подтверждение.

- Установка, секреты Stripe, рабочий IAM и runtime допуска отсутствуют в стенде. Допуск предоставляется только явно внедрённым портом; внедрённый в тестах владелец полномочий управляемый.
- Управляемый Processing проверял настоящий loopback HTTPS/mTLS и долговременный commit синтетического inbox. Код HIT-104 прочитан как образец действующего контракта; полноценная сборка и развёртывание Processing не выполнялись.
- ACKED означает установленную квитанцию Processing, в том числе HELD у получателя. Он не присваивает финансовый исход, case state или Delivery/ClickUp.
- Сценарии PostgreSQL использовали временный кластер и тестовые файлы. Промышленный диск, потеря питания, SQL TLS, нагрузка и сквозная интеграция не проверялись.
- Тестовые параметры batch/lease/backoff задаются явно в композиции, без новых требований MVP. Worker вызывается ограниченными порциями из доверенного runtime; сетевой планировщик и рабочее provisioning не добавлены.

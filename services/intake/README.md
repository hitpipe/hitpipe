# Intake: схема PostgreSQL

**Тестовый стенд обновлён на PostgreSQL 18.7 по прямому указанию пользователя.**
Закреплённый договор Project OS пока ссылается на прежний baseline; его обновление
через CCR ещё не подтверждено. Пауза задачи автоматически не снимается. 12 ноября 2026
опубликована CVE-2026-120154 (обход RLS при определённых ON CONFLICT запросах),
затрагивающая 18.6. Исправление — 18.7. Существующие положительные тесты ниже
не воспроизводят этот дефект и не доказывают безопасность версии.
См. `docs/HIT-71/README.md`. Версия и схема самостоятельно не изменены.

`migrations/0001_intake.sql` — точные SQL bytes раздела HP-MVP-SQL-INTAKE
из `hitpipe/project-os` на `fedbe40bb597e25f66aeb1172af3ff7459c81b40`,
`contracts/hitpipe/mvp-2026-10-31/formal/PERSISTENCE.md`.
Общий документ PERSISTENCE не является единой миграцией.

Миграция предназначена только для отдельной базы Intake. До её применения
должны существовать `hp_intake_app`, `hp_intake_worker`, `hp_intake_purge`:
NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOBYPASSRLS. Мигратор владеет схемой
и таблицами; рабочие роли не наследуют мигратора или роль обслуживания purge.
Миграция исполняется мигратором через `psql -X -v ON_ERROR_STOP=1`.
Она намеренно не идемпотентна: повторное применение должно завершаться ошибкой,
а не скрывать неизвестное состояние существующей базы. Откат или обновление
рабочей схемы требуют отдельного согласованного решения.

Из корня репозитория:

```sh
python3 services/intake/tools/check_postgres.py
```

Нужны Python 3 со стандартной библиотекой и работающий Docker. Скрипт использует
фиксированный digest PostgreSQL 18.7 Alpine, создаёт новый контейнер без внешней
сети и портов, хранит кластер в tmpfs и удаляет контейнер после запуска.
Он не принимает адрес существующей базы. Локальное trust-подключение доступно
только внутри этого одноразового контейнера. Bootstrap ролей в `tests/postgres`
предназначен исключительно для теста, не для рабочего развёртывания.

Проверяются объекты и полная матрица SQL-прав, реальные подключения трёх ролей,
изоляция строк по `hp.workspace_id`, отсутствие прав мигратора/чужих ролей,
особые права source_facts и глобального job_index, уникальность события в
подключении, неизменность identity/первого времени/expiry, 72 часа, 1000 сигналов
и 16 MiB, изменение/освобождение квоты и конкурентные вставки app/worker.
Тесты используют только синтетические идентификаторы и ссылки на содержимое.

Установка `hp.workspace_id` проверяет механизм изоляции строк, **не полномочия
пользователя**. Перед установкой области приложение должно отдельно проверить
актуальные IAM grant и принадлежность ресурса. Привилегированный migrator и
администратор не являются бизнес-пользователями.

Тест базы не доказывает проверку подписи, надёжное сохранение содержимого в
файлах, успешный ответ webhook, работу внешнего сервиса, сквозную интеграцию
или рабочее развёртывание. Данные сигналов, payload и секреты нельзя переносить
в SQL вместо предусмотренных схемой ссылок на содержимое.

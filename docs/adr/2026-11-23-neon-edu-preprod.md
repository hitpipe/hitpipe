# PostgreSQL для учебного стенда HitPipe

Дата — 23 ноября 2026 года.

**Решение для ближайшей сдачи — локальный PostgreSQL 18.7.** Используем закреплённый образ из проверенного браузерного прогона и постоянный том отдельного проекта Compose. Neon оставляем кандидатом для отдельного профиля с синтетическими данными.

## Почему

- Neon поддерживает PostgreSQL 18.7. В Neon вычислительный узел использует `fsync=off`, а долговременную запись обеспечивает отдельный слой хранения. Проверенная сборка HitPipe требует `fsync=on`, `synchronous_commit=on` и зафиксированную версию 18.7. HP-MVP-A-024 также требует `full_page_writes=on`. Проверку в существующем запуске сохраняем.
- Одноразовый браузерный тест создаёт базы и роли в локальном Docker-контейнере без внешней сети. Управляемой базе потребуются отдельный запуск миграций и сетевой профиль. Processing берёт сессионную PostgreSQL-блокировку при миграции. Транзакционный пул Neon эту блокировку не поддерживает.
- Neon разгрузит VPS на стоимость контейнера PostgreSQL и его данных. Следующие крупные расходы на VPS — сборка интерфейса и образов, а также Keycloak. Сборка вне VPS и доставка готовых образов остаются вариантом при малом запасе памяти.

Закреплённый образ для локального варианта:

```text
docker.io/library/postgres@sha256:75dcac3dfb1cd01ca3536910bbc84128759362f8b118bf8c55b38a94f68f3b73
```

## Условия для отдельного профиля Neon

1. В отдельном проекте с синтетическими данными проверить `SHOW server_version`, `SHOW fsync`, `SHOW full_page_writes` и `SHOW synchronous_commit`. Зафиксировать, какой тест долговременности подтверждает эквивалентность удалённого хранилища. Профиль вводится после отдельного решения руководителя по этому отличию.
2. Выделить отдельные базы или соответствующую контракту изоляцию для каждого владельца. Создавать прикладные роли через SQL с точными полномочиями, без `BYPASSRLS` и без администраторской роли Neon. Для миграций использовать прямое TLS-подключение с проверкой имени, `sslmode=verify-full`. На первом прогоне использовать прямые подключения и небольшие пулы приложения.
3. Прогнать миграции на чистой базе и их повтор по штатному порядку. Доказать отказ при доступе из чужой области, проверить отдельные роли фоновых обработчиков и миграций, а затем пройти Stripe → ClickUp с подтверждающим чтением. Повторить событие после переподключения и перезапуска. Дело должно сохраниться, число задач остаться равным одному.
4. Проверить запуск после простоя и поведение при временном обрыве соединения. Сохранять конфигурацию Neon отдельным профилем. Локальный профиль PostgreSQL 18.7 остаётся доступным для повторения учебного прогона.

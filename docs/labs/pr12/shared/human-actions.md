# Человеческие шаги перед сдачей

Это список будущих действий, не записи их выполнения.

1. Владелец GitHub снимает реальное ограничение защиты private frontend main: доступный тариф/организация либо другое явно согласованное допустимое решение; агент не делает repo публичным. После настройки повторно проверить права/required checks, сохранить точный readback.
2. Lead review/merge двух bootstrap PR. До merge агент может готовить свой PR от exact опубликованного head SHA, помечая stacked/base. Студенту нужны собственные права clone/push; общие сервисные токены Project OS не передаются.
3. Каждый студент реально задаёт вопросы пользователю/согласованному представителю. Lead организует роль/время, не генерирует ответы вместо собеседника.
4. По ring каждый студент проверяет чужой участок и получает проверку своего: requirement clarity без подсказок автора; clean environment reproduction; module contract/map/substitution. Сохранить реальный protocol, исправления, повторную проверку.
5. Lead организует назначенное преподавателем cross-project opposition и собирает реальные замечания/решения. Каждый code/requirements PR проходит содержательное человеческое review и настоящий merge после checks.
6. Участник вставляет снимки по screenshot checklist (всего21слот), проверяет страницу/фигуру/версию и скрывает секреты. Агент снимки не делает. Вносит неизвестные группу/реквизиты, проверяет пагинацию DOCX в Word/LibreOffice.
7. Уполномоченный участник фиксирует4immutable submission tags/CI/hashes каждого, экспортирует два основных03 отчёта и отдельные01 формы. Два объединённых файла не считаются согласованными преподавателем автоматически.
8. Каждый лично готовится к защите; агент может объяснить реальные изменения/проверки, но не изображает пройденную защиту.

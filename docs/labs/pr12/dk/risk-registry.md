# HIT-21 — качественный реестр рисков IAM

Оценки — инженерные суждения для выбора проверок, не измеренная частота инцидентов. Матрица из актуальной 03.02 ПР2 §2.4: низкая вероятность × небольшой/значимый/тяжёлый ущерб → низкий/средний/высокий; средняя или высокая вероятность × небольшой → средний, × значимый/тяжёлый → высокий.

| ID | Нежелательное событие → причина → последствие | Вероятность и обоснование | Ущерб | Приоритет | Проверка и частота / решение |
| --- | --- | --- | --- | --- | --- |
| DK-RISK-01 security | Истёкшая/revoked/unknown сессия признана valid → boundary/default allow → неправомерный доступ при ошибочном использовании результата | Средняя: несколько одновременных ветвей и equality | Тяжёлый | Высокий | Каждый PR: boundary/unknown/revoked tests + M01–04; business authorization остаётся отдельным обязательством production |
| DK-RISK-02 security | Недоверенный JSON принимается неоднозначно или раскрывается → duplicate/extra/case key и parser error → неверная policy/утечка | Средняя: JSON decoder допускает некоторые неоднозначности по умолчанию, один дефект реально найден в HIT-19 | Тяжёлый | Высокий | Каждый PR: strict decode, canary, malformed/size/depth cases; production transport security deferred до transport task |
| DK-RISK-03 | Старый now/lookup failure маскируется успехом → неверная последовательность ports/fallback → действие после срока | Средняя: естественная temptation cache/default | Тяжёлый | Высокий | Каждый PR: lookup→clock order, delayed lookup, safe errors/cancel, M06; live authority/latency fault injection deferred до adapter |
| DK-RISK-04 | Непроверенный host time назван trusted → time.Now принят за attestation → неверная validity | Средняя: системный clock доступен без health evidence | Тяжёлый | Высокий | Каждый PR: nil/false probe и CLI system unavailable; реальный health probe и clock-jump integration deferred с запретом production допуска |
| DK-RISK-05 | Сборка не соответствует source или не переносится → dirty tree/скрытая зависимость → невоспроизводимая сдача | Средняя: stacked PR и несколько сред | Значимый | Высокий | Каждый PR: source metadata + dev/release external-directory smoke; independent clean-room запуск человеком pending HIT-23 |
| DK-RISK-06 | Тесты зелёные, но не проверяют правило → слабые assertions/skip → ложная уверенность | Средняя: coverage statements не означает поведенческую полноту | Значимый | Высокий | Каждый PR: named nonzero tests, mutation suite; survivors → новый тест+retest; manual review oracle другим студентом pending |
| DK-RISK-07 | Неверная подстановка mutable adapter → aliasing/race → нестабильное решение | Низкая: values и stateless consumer, но будущие реализации возможны | Значимый | Средний | CI race + ownership/concurrency tests; production shared store race/load testing deferred |
| DK-RISK-08 | Ошибка подписи рисунка/персональных полей → неверная связь с версией → возврат отчёта | Средняя: 21 место снимка и 4 формы | Небольшой | Средний | Автоматическая DOCX/placeholder/link проверка при сборке; человек вставляет реальные снимки и проверяет подписи |

Высокие риски определили обязательный каждый-PR набор, а не только happy path. Отложенные integration проверки не выдаются за PASS; до их реализации модуль остаётся ограниченным учебным срезом. Manual review/peer/opposition, снимки и защита не поручаются агенту от имени других людей.

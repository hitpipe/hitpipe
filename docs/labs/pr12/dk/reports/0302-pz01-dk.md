## 2 Постановка задачи и обследование

HitPipe сопровождает бизнес-операцию от исходного события до установленного результата либо понятного ожидания/исключения. Оператору требуется доступ к своим операциям; cookie или прежний login не должны стать бессрочным разрешением. IAM policy — необходимая поддерживающая часть, но текущая роль/workspace/epoch/start gate принадлежат отдельным продуктовым правилам.

Подтверждённые документальные факты: source T/002 задаёт idle8h/absolute24h; T/003 отделяет validity от business authorization; T/013 требует минимизации данных. На исходном bootstrap личного модуля не было; теперь reusable policy/consumer/tests существуют. Это Git/source facts, а не ответы интервью.

Реальный разговор с конечным пользователем/согласованным представителем **NOT CONDUCTED**. Невозможно добросовестно подставить ответы без собеседника; вопросы подготовлены, человеческое действие остаётся HIT-23. Для каждого вопроса фактический ответ/дата/участник отсутствуют; после реального контакта они добавляются в interview.md с источником. Вопросы собственного участка:

Владелец контакта/уточнения — Дмитрий Карачебан; human review будет отдельным.

## 3 Выполнение работы

### 3.1 Требования, MVP, состояние и безопасность

Ряд ниже сформулирован в R1 до кода; точные equality/chronology/error precedence/freshness уточнены R2. Нынешний actual status: FR01–04 и локальные NFR01–02 реализованы/автоматически проверены; NFR03 имеет source/CI proof, но независимый student reproduction ещё pending. Это не приёмка всего IAM.

| ID | Требование и основание | Критерий / независимый oracle | Проверка |
| --- | --- | --- | --- |
| DK-FR-01 | При известной, неотозванной, корректной сессии и доверенном времени до обоих дедлайнов policy возвращает Valid. T/002 | Given created=2026-10-18T00:00:00Z, idle=08:00, absolute=24:00, now=07:59:59Z; When evaluate; Then Valid | Named normal test; CLI positive fixture |
| DK-FR-02 | Unknown, revoked и истекший срок дают Denied, независимо от прежней успешной аутентификации. T/002–003 | Unknown→Denied; revoked=true при будущих сроках→Denied; now после любого срока→Denied | Decision table, equivalence classes |
| DK-FR-03 | Ошибка Lookup/Clock или отсутствие зависимости не превращается в Valid. T/003 | Error-producing double→Unavailable; constructor rejects absent port; Valid отсутствует | DI/error contract tests |
| DK-FR-04 | Диагностическая команда вызывает тот же module, принимает путь fixture и формат, печатает версию/commit/build mode; malformed config даёт ненулевой exit. HIT-19, T/005 | valid synthetic fixture→exit 0 и безопасный статус; invalid JSON/format→exit !=0; `--version` связывает binary с SHA | Wrapper smoke, CLI integration tests |
| DK-NFR-01 | Для каждого из заданных входов 100 повторных вызовов чистой policy дают одинаковое решение и сохраняют исходный snapshot. Никакого IO внутри domain. T/003 | Точное сравнение решений и deep equality входа; import graph без adapters/network/filesystem | Determinism/immutability test + import guard |
| DK-NFR-02 | Обычный и ошибочный путь диагностики не выводят canary secret, session identifier, пользовательский профиль или содержимое fixture. T/013 | В stdout/stderr нет точных canary-строк; ошибки содержат только фиксированный безопасный код | Canary CLI test, captured logs |
| DK-NFR-03 | Внешние зависимости отсутствуют у pure module; Go 1.27.2 закреплён; проверки выполняются из чистого clone без клиентских credentials. HIT-16/19/21 | `go.mod`, `go list`, actual named tests и отдельный clean-clone прогон; peer reproduction остаётся human gate | Local + CI + independent-human package |

MVP HP-VER-001 — завершённая сопровождаемая операция, а не webhook→API без проверки. IAM validity поддерживает доступ к ней. В текущей порции ядро: Evaluate, Execute/ports, synthetic adapters, strict diagnostic, tests/evidence. За пределами учебного slice: SQL authority/RLS/durability, OIDC/PKCE/CSRF, session issue/renewal, tenant membership и revoke/start barriers. Они остаются целевыми обязательствами продукта; здесь их не реализовывали и не переносили из продукта «в резерв».

Начальное состояние: fixed created2026-10-18T00:00Z, initial idle08:00Z, absolute2026-10-19T00:00Z; found=true/revoked=false/trusted=true. Файлы services/iam/testdata/*.json, никаких личных cookies/секретов. Reset — повтор immutable fixture на exact commit; программа read-only, внешнего cleanup нет. File/Fixed дают один consumer; unavailable authority никогда не даёт прошлый success.

| Вопрос ранней безопасности | Конкретный ответ и решение |
| --- | --- |
| Что защищается? | Прикладная сессия как предварительное условие защищённого действия; policy не выдаёт business grant |
| Откуда недоверенный ввод? | JSON diagnostic boundary; malformed/duplicate/extra/case/null/version/size/depth отклоняются, input не печатается |
| Где проверяются права? | Текущий business authorization/start barrier отдельно; valid не «действие разрешено» |
| Реальный ущерб? | False allow для revoked/expired/unknown; утечка cookie/profile/ошибки; fail closed и минимальный snapshot уменьшают эту поверхность |
| Секреты и журнал? | Production credentials не нужны; stdout/stderr только bounded state/reason/build metadata; canary regression проверяет отсутствие секретов; raw parser/adapter errors не возвращаются |

## 2 Постановка задачи

Объект: SessionPolicy.Evaluate и application AuthenticateSession.Execute с consumer-owned SessionLookup/Clock, реальным fixture reader и fixed double. Rules: no allow unknown/revoked/expired/invalid/untrusted; expiry equality; absolute24h; minimal immutable values; lookup before clock; no fallback success on error/cancel; safe strict diagnostic. Источники ожиданий — HP-BP-001/T/002–003/013, BP007/T005 и уточнения R2, записанные до реализации. Проверки не получают expected из запуска проверяемой функции.

## 3 Выполнение работы

### 3.1 Техники и oracle

| Техника / класс | Вход и независимое ожидание | Реальные тесты |
| --- | --- | --- |
| Эквивалентные классы | Known/not revoked/correct chronology/trusted before deadlines → session_valid; unknown/revoked отдельно → denied | TestEvaluateValid/Unknown/Revoked |
| Граничные значения | Idle и absolute: −1ns допустимо, equality/+1ns истёк; 24h cap/+1ns; zero/future/unsupported year | TestEvaluateIdleBoundary/AbsoluteBoundary/InvalidChronology/ClockAndFutureCreation |
| Таблица решений | Clock > unknown > revoked > malformed > future > absolute > idle > valid, включая одновременно истинные причины | TestDecisionTablePrecedence |
| Contract substitution | Один Execute с File и Fixed: normal/error/idle equality/unknown/revoked → один oracle | TestSameConsumerContractWithBothAdapters |
| Fail closed и свежесть | Lookup error → unavailable без Clock; Clock error/untrusted → unavailable; now считывается после Lookup; cancellation до/во время ports → unavailable | TestPortErrorsDoNotAllowOrLeak, TestClockReadAfterLookupAndCancellation |
| Недоверенный ввод | Duplicate/extra/case mismatch/null/type/version/trailing/deep/oversize/invalid timestamp → config error 2; canary не печатается | TestDiagnosticMalformedAndCanary, TestAdapterFailureAndBoundaryInputs |
| Инварианты | Valid подразумевает found, not revoked, trusted, valid time interval; одинаковый input даёт одинаковое decision | FuzzValidityInvariants, TestEvaluateDeterministicImmutable |

Техник более двух: классы эквивалентности, границы±1ns, decision table; дополнительно substitution/инварианты. Виды входов включают штатные, ошибочные и граничные. Concurrency exercise проверяет value ownership, а race detector ограничен выполненными путями. Clock/System unit probe synthetic и не доказывает синхронизацию host.

### 3.2 Данные и автоматизация

Fixed synthetic timestamps/booleans; no secrets/network/customer data. Bootstrap source lock проверяется205files. В чистом clone exact SHA с Go1.27.2 и Python3.10+: root `python3 tools/pr12/workspace.py validate`, `PR12_RACE=1 python3 tools/pr12/workspace.py check iam --require`, `python3 tools/pr12/workspace.py smoke iam --require`. Wrapper требует непустые named tests и реальные pass events, не считает skip/TODO успехом. Отдельный `go test -coverpkg=./...` объединяет coverage CLI→adapter calls. Личная сторонняя проверка остаётся HIT-23; собственный CI не называется другим студентом.

### 4.2 Анализ покрытия

Cross-package профиль iam-all.cover дал94.5% statements, Evaluate/Decision.IsValid/Service.Execute100% statements. Обычный package-local профиль не включает adapter-вызовы из CLI binary, поэтому добавлен дополнительный scope `-coverpkg=./...`; проценты отдельных test binaries не являются процентами всего service. Ни один показатель не branch/requirement coverage proof.

Конкретные gaps: main os.Exit не вызывается внутри unit-test процесса, но реально исполняется smoke; defensive composition-root errors при уже сконструированных nonnil dependencies, часть malformed JSON closing-token/невалидных timestamp returns; nil-classification default для экзотических Go interface implementers. Ряд read/output failure branches дополнен regression tests. Остальное не маскируется: exhaustive JSON grammar fuzzing/OS fault matrix отложены, core coverage не доказывает SQL freshness, OIDC, tenant authorization, revocation, distributed state или host clock health. Решение и риск записаны в test-results.md/risk-registry.md.

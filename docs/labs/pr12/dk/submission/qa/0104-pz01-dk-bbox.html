Корректный запрещающий результат — например, истёкший срок — является обработанным бизнес-исходом и имеет код завершения 0. Неверный JSON или неизвестный формат дают код 2. Недоступная зависимость даёт код 3. Команда выполняет один сценарий и завершается. Она не хранит состояние между запусками и не меняет исходный JSON. Повторный запуск с теми же значениями и фиксированным временем даёт тот же результат. После ошибочного файла восстановление состоит в выборе корректного входа; очистка внешних ресурсов не требуется. 11 4 РЕЗУЛЬТАТЫ 4.1 Проверки компонента Сценарий Ожидание и фактический результат --version Выведены версия исходников, признак dirty и режим сборки; проверка успешна в dev и release. valid.json, text/json session_valid, код 0; присутствуют начальная и конечная диагностические записи. idle-equal.json denied/idle_expired, код 0: равенство срока означает истечение. malformed.json и invalid_config, код 2; содержимое входа не неверный формат раскрывается. --lookup file/fixed Тот же потребитель получает одинаковый результат при одинаковых данных. --clock system без unavailable/clock_unavailable, код 3. подтверждения Неподтверждённое системное время не считается исправности часов доверенным.

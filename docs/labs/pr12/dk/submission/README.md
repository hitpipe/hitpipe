## Проверка и происхождение результатов

- `quality-audit.json` — целостность DOCX, сохранность текста, шрифт, интервал, отступ, рамки и подписи.
- `visual-validation.json` — проверенные страницы и точные SHA-256 DOCX/PDF. Визуальная проверка авторского пакета не объявляется независимым повторным approval.
- `qa/` — настоящие PDF из LibreOffice Writer, текст, встроенные шрифты, границы страницы и журналы. Проверено 92 страницы; лишняя пустая страница устранена.
- `capture-manifest.json` — источники, версии и SHA-256 29 PNG. Они занимают 20 из 21 обязательных мест; отсутствует только снимок не состоявшегося межпроектного оппонирования.
- `evidence/` — исходные журналы, фактические сведения GitHub API, read-only браузерные представления, PNG. Такие представления прямо подписаны; они не имитируют интерфейс терминала или GitHub.
- `font-provenance.json` — локально использованы настоящие Times New Roman; файлы шрифтов не распространяются в репозитории.
- `artifact-manifest.json` — состав архива, файлы и контрольные суммы.
- `criteria-crosswalk.json` — состояния всех 29 результатов методичек, без повышения статуса отсутствующих человеческих процедур.

PR №12–19 фактически объединены в main `73aef8d976c9f0676ee568d8dc5a82c8d35a2f00`, обязательные проверки успешны. Техническое ревью опубликовано Codex по делегации Тимофея; после исправлений владелец разрешил merge без повторного approval. Защиты не менялись. Фактический исполнитель повторных технических проверок Processing — Codex по поручению Дмитрия; это не выдаётся за засвидетельствованный личный запуск студента. Источники IAM и его тесты между C3 и main идентичны.

Историческая текстовая редакция в `../reports/` сохранена как часть истории ревью. Использовать для документов следует текущую `submission/`.

## Воспроизведение оформления

`python3 build_reports.py` использует python-docx 1.2.0 и lxml. `render_reports.py` обновляет оглавления и экспортирует PDF через совместимые LibreOffice Writer + pyuno и Poppler. После изменения исходного текста нужно повторить сборку, экспорт и проверку. `verify_submission.py` использует только стандартную библиотеку и включён в существующий CI пакета DK.

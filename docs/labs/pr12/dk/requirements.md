## Пользователь, проблема и процесс

Оператор HitPipe должен видеть свои операции и выполнять только допустимые действия. Проверка срока прикладной сессии — необходимая предварительная проверка; роль, workspace, epoch и старт конкретного защищённого действия проверяются другими владельцами. Без этого разделения успешный вход или сохранённая cookie могут ошибочно стать бессрочным бизнес-разрешением.

Текущий подтверждённый baseline: общий учебный каркас опубликован, личный IAM-модуль на исходном теге отсутствует. Описание потребностей здесь получено анализом закреплённых документов и поручения Lead. Реальный разговор с конечным пользователем не проведён; протокол [interview.md](interview.md) честно отмечает это ограничение.

## Основной и ошибочный сценарии

1. Будущий IAM-потребитель получает от своего SessionLookup минимальный snapshot и явное доверенное серверное время через Clock.
2. Чистая SessionPolicy устанавливает пригодность сессии по предоставленным фактам.
3. При пригодной сессии потребитель возвращает только результат проверки сессии. Для защищённого действия всё равно требуются текущие бизнес-полномочия и start gate.
4. Неизвестная, отозванная, просроченная или некорректная сессия отклоняется. Недоступное хранилище/время возвращает безопасную недоступность, а не разрешение.

Место в MVP HP-VER-001: часть IAM, поддерживающая основной сценарий Operations; это не весь IAM и не самостоятельный минимальный продукт. В этом срезе обязательны чистая policy, реальный application consumer, два взаимозаменяемых источника синтетических snapshot, диагностика, tests и evidence. Резерв учебного среза: SQL adapter, OIDC/PKCE/CSRF, создание и обновление сессии, runtime revoke barrier. Они остаются обязательствами целевого продукта; перенос за пределы этой лабораторной не удаляет их из MVP.

## Проверяемые требования R1

| ID | Требование и основание | Критерий / независимый oracle | Проверка |
| --- | --- | --- | --- |
| DK-FR-01 | При известной, неотозванной, корректной сессии и доверенном времени до обоих дедлайнов policy возвращает Valid. T/002 | Given created=2026-10-18T00:00:00Z, idle=08:00, absolute=24:00, now=07:59:59Z; When evaluate; Then Valid | Named normal test; CLI positive fixture |
| DK-FR-02 | Unknown, revoked и истекший срок дают Denied, независимо от прежней успешной аутентификации. T/002–003 | Unknown→Denied; revoked=true при будущих сроках→Denied; now после любого срока→Denied | Decision table, equivalence classes |
| DK-FR-03 | Ошибка Lookup/Clock или отсутствие зависимости не превращается в Valid. T/003 | Error-producing double→Unavailable; constructor rejects absent port; Valid отсутствует | DI/error contract tests |
| DK-FR-04 | Диагностическая команда вызывает тот же module, принимает путь fixture и формат, печатает версию/commit/build mode; malformed config даёт ненулевой exit. | DK-NFR-02 | Обычный и ошибочный путь диагностики не выводят canary secret, session identifier, пользовательский профиль или содержимое fixture. T/013 | В stdout/stderr нет точных canary-строк; ошибки содержат только фиксированный безопасный код | Canary CLI test, captured logs |

HIT-16/19/21 | `go.mod`, `go list`, actual named tests и отдельный clean-clone прогон; peer reproduction остаётся human gate | Local + CI + independent-human package |

Это целевые обязательства с запланированными oracle, а не измеренные PASS. Таблица фактических результатов будет заполнена после реализации. NFR-01 — измеримый локальный критерий, а не обещание throughput или доступности продукта.

## Исходные данные и воспроизведение

Все данные синтетические. Фиксированная дата 2026-10-18T00:00:00Z служит началом жизни; первоначальный idle=+8h, absolute=+24h. Набор содержит normal, unknown, revoked, просроченный idle, просроченный absolute, некорректный порядок времён, недоверенное время и malformed JSON. Нет реальных cookies/секретов/PII, нет случайного seed и сетевого provider.

Точная спецификация входов — [fixture-spec.md](fixture-spec.md). C1 поместит файлы в `services/iam/testdata`; reset — восстановить неизменяемые fixture из заданного commit и повторить команду, без БД или стороннего аккаунта. Документы [security-baseline.md](security-baseline.md) и [requirements-trace.json](requirements-trace.json) связывают угрозы, требования и проверки.

## Что требует дальнейшего уточнения

## TP-REV-001: строгие имена JSON-полей

Изначальный parser использовал `encoding/json` с DisallowUnknownFields, но это не исключало регистронезависимые aliases имён Go-полей. Например, `amount_refunded` и `AMOUNT_REFUNDED` могли последовательно записать одно типизированное поле. Это расходилось с объявленным строгим контрактом fixture. Scope ограничен офлайн диагностикой; источник не объявляется аутентифицированным provider payload.

Исправление проверяет точное имя по существующим JSON tags перед типизированным декодированием, сохраняя запрет точных дубликатов, unknown keys, trailing JSON и невалидных чисел. Второй изменяемой схемы или внешней библиотеки нет. Добавлены проверки aliases, shadowing в обоих порядках и сохранности известного нуля. Продуктовые financial predicates и приоритет причин не изменены.

Исходная red-проверка, тестовая постановка и результаты после исправления приложены. Исходные журналы/coverage/мутации Тимофея остаются историческими доказательствами его SHA и не переписаны. Новое замечание относится к этому отдельному review.

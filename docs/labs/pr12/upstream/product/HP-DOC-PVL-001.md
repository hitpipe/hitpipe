# Product Versioning Ladder — HitPipe

**ID документа:** HP-DOC-PVL-001. **Рабочее состояние:** In Review. **Ответственный за содержание и интеграцию:** Codex, делегированный Product Owner. **Назначение:** полные положительные определения состава и зрелости продуктовых версий по каноническим ссылкам; без повторного авторства FR, RULE, NFR или стратегического порядка.

Это законченные определения планируемых продуктовых ступеней, предложенные для source acceptance. Реализация, достигнутая зрелость, выпуск и формальная приёмка источников не заявлены. Точный набор опубликованных revisions, их snapshots и Contract-проекции закрепляется итоговым source manifest. До его правомерной приёмки используется явно кандидатный Discovery/Product context. Product Version, revision этого документа, версия конфигурации операции и номер сборки различаются.

## 1. Логика продуктовых ступеней

Основания — [HP-VIS-D-001](HP-DOC-VISION-001.md#HP-VIS-D-001), [HP-VIS-D-002](HP-DOC-VISION-001.md#HP-VIS-D-002), [HP-VIS-D-004](HP-DOC-VISION-001.md#HP-VIS-D-004), [HP-VIS-D-009](HP-DOC-VISION-001.md#HP-VIS-D-009), [HP-VIS-D-011](HP-DOC-VISION-001.md#HP-VIS-D-011). Развитие проверяет одну целую сопровождаемую операцию, затем повторяемое использование нескольких операций той же формы, затем публичную эксплуатационную зрелость уже определённого опыта. Новая интеграция или универсальный агент не нужны для различения этих трёх ступеней.

| Ступень — навигация | Продуктовая роль — представление | Каноническое определение |
| --- | --- | --- |
| HP-VER-001 — MVP: одна сопровождаемая операция | Ограниченный пилот целого handoff | [HP-VER-001](#HP-VER-001) |
| HP-VER-002 — повторяемая работа команды | Несколько различимых операций того же pack/pair | [HP-VER-002](#HP-VER-002) |
| HP-VER-003 — публичная эксплуатационная зрелость | Тот же TEAM-опыт при публичном качестве и проверенной готовности обслуживания | [HP-VER-003](#HP-VER-003) |

Общие нормы для каждой записи версии: все [HP-POL-001–005](HP-DOC-VISION-001.md), определения и применимые [HP-RULE-001–014](HP-DOC-SHARED-001.md), локальное [HP-RULE-101](HP-CAP-002.md#HP-RULE-101), все [HP-NFR-001–014](HP-DOC-NFR-001.md) в собственной применимости. Для HP-NFR-002/004/014 каждая версия ниже выбирает точные варианты; другие NFR действуют без ослабления. Это общая ссылка на владельцев норм, а не автоматическое включение всех функций CAP или будущих версий.

## 2. Полные определения продуктовых версий

### HP-VER-001

**Название:** MVP — одна сопровождаемая операция. **Тип содержания:** нормативное определение планируемой версии; кандидат в source acceptance.

**Ценность и контекст версии:** выбранный владелец бизнеса настраивает первую поддерживаемую операцию естественным языком, принимает её конкретный смысл и получает постоянное сопровождение оплаченного заказа до установленного handoff либо понятного незавершённого исхода. Ограниченный пилот может иметь управляемый onboarding по HP-CAP-001; обычные заказы исполняются без скрытой ручной работы поддержки.

**Закреплённый нормативный контекст:** HP-DOC-VISION-001, HP-DOC-SHARED-001, четыре выбранных Module ниже, HP-DOC-NFR-001 и эта точная запись HP-VER-001 разрешаются через итоговый source manifest. Материальные источники происхождения и кандидатный upstream Discovery сохраняются в source closure; индекс PRD не добавляет норм.

Контрольная среда и фактическая эксплуатация обозначены раздельно; ухудшение качества не скрывается прежним успешным окном |
| HP-VER-003/COND/OPERABILITY | Публично обещанный ограниченный сервис может сопровождаться ответственными людьми | HP-CAP-003/004; HP-POL-003/005; HP-NFR-008/009/013/014 | Проверить фактические владельца обслуживания и процедуру реакции/доступа поддержки/удаления в разрешённой области; применить критерии продукта к контролируемому инциденту. Не добавлять обещание круглосуточного human support, если оно не установлено отдельными условиями |

**Канонические записи evidence и выпуска:** actual implementation evidence, checkpoint и решение о выпуске пока не представлены. Их отсутствие не мешает завершить нормативное определение, но не позволяет отметить ни одну версию реализованной, проверенной или выпущенной. Формальная source acceptance, технический фазовый допуск, готовность к пилоту и коммерческое решение о масштабировании — разные записи. Последовательность стратегических проверок принадлежит [HP-DOC-ROADMAP-001](HP-DOC-ROADMAP-001.md).

## Контроль перед source review

Каждая версия имеет собственный полный положительный scope четырёх coherent profiles, канонический глобальный контекст, точные NFR-варианты и отдельные критерии зрелости. Источники поведения/качества не переиздаются. Неопределённость спроса и будущая реализация сохранены; формальные source acceptance и release evidence требуют фактических записей. Эта запись — авторский контроль состава, не независимый review и не разрешение Development.

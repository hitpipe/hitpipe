# Exact compatibility inputs for HitPipe Architecture candidate

These are exact tested dependency and tool manifests, not an implemented HitPipe platform. `go-runtime` is the compatibility fixture dependency set including selected JCS v1.0.2; its fixture module identity is intentional. Service owners initialize their own modules and select the relevant dependency subset without changing pins silently. `go-codegen` pins the generator and transitive compiler inputs. Frontend and Python manifests are the actual compatibility-spike locks, not new product features. SDKs, caches, node_modules, browsers and secrets are excluded.

`github.com/gowebpki/jcs v1.0.2` is selected for durable Go→Go message canonicalization only. Python AI and Next BFF do not originate these durable messages in MVP and do not require a second JCS implementation. Apache-2.0 license is verified from the upstream exact release source. Standard JSON sorting/serialization is not substituted for JCS. Its upstream module declares Go1.21 and no nonstandard production imports; compatibility was actually tested with Go1.27.2. Test-only dependency declarations are distinct from runtime imports.

Observed compatibility evidence is under `checks/stack/results` and `checks/formal` in the source package. These fixtures confirm lock resolution, production frontend build, bounded browser/unit/generator/transport/schema checks. They do not claim live provider permissions, full product E2E, release SLOs, distributed revocation correctness or deployment qualification. Changes require relevant revalidation and revised exact pins.

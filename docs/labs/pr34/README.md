# HitPipe · практические работы № 3 и № 4 к 30.11

Пакет v1 для эпика HIT-160. Каждый участник сдаёт **четыре личных отчёта DOCX**. Таблица ниже помогает спланировать работу. Полные критерии, шаблоны и обязательные снимки перечислены в четырёх исходных методичках из папки [methodics](methodics). [Манифест](manifest.json) указывает названия оригиналов, контрольные суммы и исходные версии проекта после QE.

## Как выполнять и сдавать

1. Запустить личную задачу Project OS по обычному /start. Выбрать свой модуль, зафиксировать исходный коммит, версии инструментов, код участника, стенд и настройки. Для каждого эксперимента заранее записать гипотезу, условия, измеряемую величину и ожидаемый результат.
2. Выполнить прогоны на своём изменении и сохранить команды, исходные логи, замеры и результаты тестов. Для снимков использовать реальный вывод своей машины, стенда или CI. Подписывать снимки и привязывать их к конкретным пунктам методички. Для внешних сервисов использовать тестовые подключения, секреты и личные данные закрывать.
3. В PR со значимым изменением пригласить участника команды для независимой проверки, самому провести ревью чужого PR, ответить на полученные замечания и приложить ссылки на обсуждения. Это нужно по МДК 03.02 № 3. Общий CR-001 и работа со стендом могут быть общими, а эксперименты, выводы, скриншоты и вклад у каждого свои.
4. Положить четыре DOCX по образцу прошлой сдачи и приложить к карточке ссылки на исходники, PR, CI, протоколы и точные коммиты. Теги ставить на проверенные коммиты отчётов по схемам из методичек. Существующие теги сохранять, исправленную сдачу отмечать следующей версией.
5. Человек передаёт комплект на приёмку по инструкции карточки. Для этого эпика проверка отчётов человеческая.

## Что понадобится от человека

- Выбрать значимый фрагмент своей части, подтверждать план /start и лично передавать готовый комплект.
- Сделать снимки реальных результатов, если агент не видит вашу машину или CI.
- Договориться с коллегой о взаимном ревью и оставить содержательные комментарии от личного аккаунта.
- Если для Миллса неясно n или в старом комплекте не хватает снимков, свериться с задачей лида по протоколам ПР 2. Итоги ревью и число комментариев сами по себе не устанавливают n.
- На защите самостоятельно повторить действие по заданию преподавателя и объяснить свой вывод. Методички предусматривают выполнение действий на защите без генеративного ИИ.

## Техническое ревью для HIT-162

Codex по поручению Тимофея Патрушева. База `a226778c6e40bac897965370ef43ce7b7fa6b369`, проверенный коммит `ea4e3a9432337c403011e7cffe4ad2a165ef9863`.

| Пункт проверки | Результат |
| --- | --- |
| Назначение и состав | Четыре файла Delivery. Приём сохраняет точные параметры назначения, адаптер выполняет одну попытку создания и проверяет результат по известному ID. |
| Сложность и дублирование | Cyclomatic = 1 + if, циклы, недефолтные ветви, вхождения && и \|\|. `DecodeIntent` 29 → 29. `TestPostgresDurableIntake` 66 → 70. Новый `Create` — 7, `Verify` — 13, `readJSON` — 7, `assignee` — 7 и `New` — 2. Точных совпадений пяти последовательных значимых строк после токенизации нет в обеих версиях. Проверено 147 → 206 строк реализации и 318 → 387 строк тестов в четырёх файлах diff. Правила разбора ответа и проверки назначения используются совместно. Повторяются две настройки HTTP-запроса (авторизация и закрытие), смысловую согласованность важно сохранять при будущей правке транспорта. Проверки формата доставки и ограничений ClickUp относятся к разным контрактам. |
| Анализатор | Go 1.27.2 и Staticcheck 2026.2.2, `-checks=all`. Для `internal/intake` до и после `vet` успешен, Staticcheck даёт тот же список из четырёх ST1000. Для нового `internal/clickup` оба анализатора прошли. |
| Граничные случаи | Пройдены сценарии неопределённой записи без повтора, несовпадения назначения и неполного ответа. Проверки по отдельному несовпадению ID/заголовка и точной границе размера ответа следует добавить. |
| Тесты | Пакетные тесты Intake прошли на обеих версиях, три теста ClickUp — на новой. Прогон на Darwin/arm64 с тестовым транспортом. Linux-сценарий PostgreSQL в рамках этого ревью только прочитан. |
| Документация и границы | Описание PR и комментарии указывают границы допуска, записи и проверки результата. Интеграция полного рабочего цикла и проверка реального аккаунта остаются отдельной работой. |

**[Предложение]** В [Verify](https://github.com/hitpipe/hitpipe/blob/ea4e3a9432337c403011e7cffe4ad2a165ef9863/services/delivery/internal/clickup/client.go#L118-L123) ID и заголовок сверяются независимо. В [TestVerifyRejectsMismatch](https://github.com/hitpipe/hitpipe/blob/ea4e3a9432337c403011e7cffe4ad2a165ef9863/services/delivery/internal/clickup/client_test.go#L83-L98) эти поля в полных ответах неизменны. Неполный ответ будет отклонён и после удаления одного из сравнений. Предлагаю два среза теста, где меняется ровно одно поле, и в каждом ожидается `ErrMismatch`. Это проверит, что задача с неверным ID или заголовком не признаётся результатом.

**[Предложение]** Для [readJSON](https://github.com/hitpipe/hitpipe/blob/ea4e3a9432337c403011e7cffe4ad2a165ef9863/services/delivery/internal/clickup/client.go#L140-L156) добавить пару тестов с синтетическим ответом допустимой длины 256 КиБ и ответом длиннее на 1 байт. Это зафиксирует принятую границу и обнаружит случайное изменение оператора сравнения.

**Вывод.** Изменение соответствует заявленной границе адаптера по прочитанному коду и локальным тестам. Пакет ClickUp проходит анализ без находок. Предложения уточняют покрытие отдельных правил и не подтверждают полную интеграцию.

# Показ с внешними Stripe Sandbox и ClickUp

Этот профиль включается для одной выбранной рабочей области. Контейнер сохраняет закрытую сеть. Выделенный Unix-сокет даёт ему только чтение необходимых объектов закреплённого Stripe Sandbox и создание или чтение задач в одном заранее выбранном списке ClickUp. Сервер проверяет принадлежность списка этому ClickUp и владельца API-токена.

Отдельный шлюз принимает событие только на `/webhooks/stripe/demo`. Он сверяет рабочую область и аккаунт из защищённого манифеста готовности, сохраняет исходное тело и заголовок подписи. Внутренний обработчик фиксирует поступление до пересылки в Intake. Intake проверяет подпись независимо, использует заключённую привязку Sandbox и сохраняет идемпотентность. Результат ClickUp читается существующим Delivery по идентификатору созданной задачи.

Подключение описано в [исходниках брокера](../broker/PROVIDER_PROFILE_RU.md). Аккаунт, тариф, рабочая область ClickUp, список и исполнитель задаются в закрытом конфигурационном файле. Подпись услуги показывает каталог, её вводит владелец при составлении операции. Учебные платёж и помощник на этом профиле скрыты.

Профиль Intake собирается с `intake-qualification-workspace.patch` и затем с `intake-provider-sandbox.patch`. Внешняя версия протокола совпадает с версией webhook `2026-09-30.endive`. Прежний профиль сохраняет прежние настройки.

Локальные проверки шлюза и исходящих запросов выполняются из этого каталога командой `python3 -B -m unittest test_provider_egress test_school_stripe_ingress`. Проверки оболочки, каталога и сборки входят в отдельный протокол. Для подтверждения реального сценария нужен платёж со Stripe Checkout в Sandbox, независимое чтение задачи ClickUp и повтор того же события.

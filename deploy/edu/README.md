# Учебный стенд HitPipe

Профиль запускает интерфейс и владельцев Intake, Processing и Delivery для синтетического сценария Stripe → ClickUp. Провайдеры локальные. В этом профиле сессия заранее выделена для одного тестового пользователя. Слушатели привязаны к loopback. Конфигурация реального IAM проверяется отдельно.

## Подготовка

1. Возьмите ревизию интерфейса и архив `hitpipe-demo-browser.tar.gz`, указанные в `sources.lock`. Сверьте SHA-256 архива и распакуйте его в пустой каталог. В `tooling/pr12/frontend` на Node 24.22.0 и npm 11.19.1 выполните `npm ci --strict-peer-deps`, `npm run build -- --webpack` и `npx playwright install chromium`. Для бэкенда подготовьте Docker и Go 1.27.2, загрузите образ PostgreSQL 18.7 по дайджесту из `sources.lock`. Первый запуск соберёт серверные бинарники и создаст постоянный том.
2. Скопируйте `hitpipe-school.env.example` в `~/.config/hitpipe-school.env` с правами 0600. Укажите абсолютные пути к распакованным исходникам, собранному интерфейсу, Node, Go, серверному запуску и генератору тестового события. Рабочие данные держите отдельно от исходников.
3. Положите `hitpipe-school.service` в `~/.config/systemd/user/` и запустите.

```bash
systemctl --user daemon-reload
systemctl --user enable --now hitpipe-school.service
systemctl --user status hitpipe-school.service
```

Адрес для входа в учебный сценарий сохранён в закрытом файле `current/web-ready.json` в каталоге состояния. Для показа с другого компьютера используйте SSH-проброс двух локальных портов. Пример для стандартных портов:

```bash
ssh -L 3108:127.0.0.1:3108 -L 3109:127.0.0.1:3109 deploy@hitpipe-codex
```

## Проверка одного чистого прогона

Из каталога этого файла:

```bash
set -a
source ~/.config/hitpipe-school.env
set +a
./smoke.sh browser
```

Проверка включает подтверждение операции в браузере, подачу подписанного события и его дубликата, одно создание задачи ClickUp, чтение результата и статус `CONFIRMED`. Протокол и снимки сохраняются рядом с `web-ready.json`. Путь к `browser-proof.json` из первого прогона сохраните перед перезапуском. После перезапуска выполните `./smoke.sh persisted-case /путь/к/browser-proof.json`. Проверка сверяет прежние идентификаторы, подтверждённое чтение и состояние дела.

Для ручного показа на чистом экземпляре откройте адрес входа, подготовьте операцию, пройдите проверку и репетицию, затем явно включите операцию. После появления состояния «Активна» запустите `./smoke.sh stripe paid` на VPS. Откройте список и карточку дела. Команда `./smoke.sh stripe replay` подаёт то же событие повторно, а `./smoke.sh stripe status` показывает количество дел, созданий и чтений ClickUp. Привязка учебного Delivery действует 90 минут. Перезапуск перед показом обновляет её и сохраняет дела.

При сообщении о недоступности управления нажмите «Прочитать состояние операций». Если операция уже активна, откройте её и продолжите с события Stripe. Если состояние пустое, повторите проверку и репетицию с тем же черновиком.

Для показа помощника включите `HITPIPE_SCHOOL_AI=1`. В настройке операции откройте учебного помощника и отправьте тестовый запрос. Кнопка «Внести в поля черновика» применяет подсказку к форме. Черновик сохраняется отдельным действием.

## Остановка

```bash
systemctl --user stop hitpipe-school.service
```

Данные PostgreSQL и содержимое дела остаются в томах. Для повторного чистого прогона остановите первоначальный экземпляр, освободив порты 8443 и 9443. Укажите отдельное значение `HITPIPE_SCHOOL_INSTANCE` и отдельный каталог состояния.
